# C++ 容器性能优化：用 Vector 模拟 Stack

在算法竞赛和高性能计算场景中，`std::stack` 的默认实现可能会带来不必要的性能开销。使用 `std::vector` 模拟栈通常能获得显著的性能提升。

## 核心差异

| 特性           | `std::stack` (默认基于 `std::deque`) | `std::vector` (模拟栈)               |
| :------------- | :----------------------------------- | :----------------------------------- |
| **底层实现**   | `std::deque` (双端队列)              | `std::vector` (动态数组)             |
| **内存布局**   | **分段连续** (Chunked)               | **严格连续** (Contiguous)            |
| **缓存友好性** | 较差 (跨段访问可能导致 Cache Miss)   | **极佳** (利用 CPU 预取与缓存局部性) |
| **内存分配**   | 即使数据量小也可能有多次分配         | 可通过 `reserve()` 一次性分配        |

### 1. 内存布局对比

- **`std::deque`**: 为了支持 $O(1)$ 的头尾插入/删除，其内部由多个定长的内存块（chunks）组成，通过一个中央控制器（map）管理。这意味着数据在物理内存上不是完全连续的。
- **`std::vector`**: 保证所有元素在物理内存中是连续存储的。这对于 CPU Cache Line 极其友好，因为读取一个元素时，相邻的元素很可能已经被预取到 L1/L2 缓存中。

### 2. 性能测试结论

在频繁进行 `push` 和 `pop` 操作的场景（如单调栈问题）中，使用 `std::vector` 模拟栈往往比直接使用 `std::stack` **快一倍甚至更多**，且内存占用更低。

## 代码实现范例

### ❌ 普通写法 (使用 std::stack)
```cpp
stack<int> st;
st.push(1);
st.pop();
int top = st.top();
```

### ✅ 优化写法 (使用 std::vector)
```cpp
vector<int> st;
// 预分配内存，避免扩容开销（如果知道大致规模）
st.reserve(n); 

// 入栈
st.push_back(1); 

// 出栈
st.pop_back(); 

// 获取栈顶
int top = st.back();
```

## 最佳实践

1. **优先选择 Vector**: 在不需要标准栈接口约束的情况下，优先使用 `std::vector` 并配合 `push_back`/`pop_back`/`back` 操作。
2. **预分配内存**: 如果能够预估最大深度（例如 $N$），务必调用 `st.reserve(N)`，这能完全消除动态扩容带来的内存拷贝开销。
3. **数据结构精简**: 栈中尽量只存索引 (`int`) 而非对象或配对 (`pair`)，进一步减小内存带宽压力。
