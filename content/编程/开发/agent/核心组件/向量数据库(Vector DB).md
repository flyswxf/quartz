## 概述
向量数据库（Vector Database）是一种专门设计用于高效存储、索引和查询高维向量数据的存储系统。在 Agent 架构中，它是实现 [[记忆(Memory)#长期记忆 (Long-Term Memory)|长期记忆]] 的基石。

大语言模型通过将现实世界的数据（文本、图像、代码等）映射为包含数百或数千个维度的浮点数数组（Embeddings），从而捕捉数据的语义特征。向量数据库的任务就是管理这些数组，并在需要时快速找到最相似的记录。

## 核心原理

### 1. 向量化 (Embedding)
将非结构化数据转化为机器可理解的数值表示。
- 相似的概念在多维空间中的距离更近（例如，“狗”和“小狗”的向量距离，比“狗”和“汽车”的距离要近得多）。
- 常用模型：OpenAI 的 `text-embedding-3` 系列、HuggingFace 的 `BGE` 模型等。

### 2. 相似度计算 (Similarity Metrics)
数据库在检索时，需要衡量 Query 向量与数据库中已有向量的相似度。主流度量方式包括：
- **余弦相似度 (Cosine Similarity)**：测量两个向量之间夹角的余弦值，最常用于文本检索（只关注方向，不关注绝对长度）。公式：$$Cosine(A, B) = \frac{A \cdot B}{||A|| \cdot ||B||}$$
- **欧氏距离 (L2 Distance)**：测量两个点在空间中的直线距离。
- **内积 (Dot Product)**：向量直接相乘，适用于经过归一化处理的向量。

### 3. 索引算法与近似最近邻 (ANN)
在海量数据中进行精确的穷举搜索（KNN）极其耗时。因此，向量数据库采用近似最近邻（Approximate Nearest Neighbor, ANN）算法，用极小的精度损失换取极大的速度提升。
- **HNSW (Hierarchical Navigable Small World)**：基于多层图结构的算法。搜索时从顶层（稀疏图）开始快速定位大区域，然后逐层向下（密集图）精细搜索。目前综合性能最优、使用最广。
- **IVF (Inverted File Index)**：通过聚类算法将空间划分为多个区域（Voronoi Cells），查询时只搜索最相关的几个区域。

## 向量数据库在 Agent 中的典型工作流
1. **记忆写入**：Agent 将重要对话或学习到的新知识（如项目文档）生成 Embedding，附加元数据（Metadata，如时间戳、来源），存入数据库。
2. **记忆触发**：当 Agent 接收到新任务时，首先对任务文本进行 Embedding。
3. **上下文检索**：在向量数据库中进行 Top-K 检索，找出最相关的 $K$ 条历史记录。
4. **决策融合**：将检索出的记忆以自然语言的形式插入到 System Prompt 或上下文中，辅助模型生成回答。

## 主流向量数据库
- **Chroma / FAISS**：轻量级，通常嵌入在 Python 应用中运行，非常适合本地 Agent 开发和原型验证。
- **Milvus / Qdrant**：企业级分布式向量数据库，支持高并发、十亿级数据规模。
- **Pinecone / Weaviate**：全托管的云原生向量数据库（SaaS），免去部署维护的烦恼。
