## 概述
Harness 的核心不是某一次模型调用，而是一次任务在系统内部如何被推进。运行时循环（runtime loop）描述的是 Agent 从接收请求到输出答案这一过程中的状态迁移规则。

它与 [[工具调用(Action)#完整执行生命周期|工具调用]] 的关系是：工具调用描述单次动作的完整闭环，而运行时循环描述整个任务级别的总控逻辑。

## 运行时循环的最小闭环
一个最小可用的 Agent harness 循环通常包含如下阶段：

1. `INIT`：初始化运行会话、预算与状态。
2. `BUILD_CONTEXT`：组装 prompt、记忆和工具规格。
3. `CALL_MODEL`：调用模型获得下一步决策。
4. `PARSE_DECISION`：判断结果是最终回答还是工具调用。
5. `EXECUTE_TOOL`：执行工具并收集 observation。
6. `UPDATE_STATE`：写入中间状态、预算与日志。
7. `TERMINATE`：输出最终答案或错误状态。

一个更形式化的表达可以写为：
$$S_{t+1} = f(S_t, Model(S_t), Tool(S_t))$$

其中 $S_t$ 表示第 $t$ 步的会话状态。

## 为什么要显式建模状态机

### 1. 便于限制预算
系统可以明确限制最大步数、最大工具调用次数、最大 wall-clock time。

### 2. 便于错误恢复
当工具超时、模型输出非法格式或中间结果为空时，可以进入专门的异常分支，而不是让整个系统直接崩溃。

### 3. 便于回放与调试
状态机让每一轮输入、输出、观察结果都可追踪，适合接入 [[Harness Engineering/06_评测与可观测性#回放与复现实验|回放系统]]。

## 状态对象通常包含什么
- `run_id`：一次运行的唯一标识。
- `user_input`：原始用户请求。
- `messages`：当前消息历史。
- `step_index`：当前执行到第几步。
- `tool_calls`：已经发起的工具调用次数。
- `status`：当前状态，如 `running`、`completed`、`failed`。
- `scratchpad`：中间推理产物或结构化工作区。
- `final_answer`：最终答案。
- `last_error`：最近一次异常。

## 退出条件
一个工程上可靠的 harness 必须显式定义退出条件：
- 模型给出最终答案。
- 达到最大步数。
- 达到最大工具调用次数。
- 达到总耗时上限。
- 命中高风险策略拦截。
- 连续多次解析失败或工具失败。

## 规范实现示例
下面给出一个偏生产化的最小运行时循环实现。代码重点不在“最少行数”，而在职责清晰、异常安全和便于扩展。

```python
from __future__ import annotations

import time
import uuid
import logging
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Protocol

logger = logging.getLogger(__name__)


class AgentStatus(str, Enum):
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"


@dataclass(slots=True)
class ToolCall:
    name: str
    arguments: dict[str, Any]


@dataclass(slots=True)
class ModelDecision:
    final_answer: str | None = None
    tool_call: ToolCall | None = None


@dataclass(slots=True)
class AgentState:
    run_id: str
    user_input: str
    messages: list[dict[str, Any]] = field(default_factory=list)
    step_index: int = 0
    tool_calls: int = 0
    status: AgentStatus = AgentStatus.RUNNING
    final_answer: str | None = None
    last_error: str | None = None


@dataclass(slots=True)
class RuntimeBudget:
    max_steps: int = 8
    max_tool_calls: int = 8
    max_elapsed_seconds: float = 30.0


class ModelClient(Protocol):
    def decide(self, messages: list[dict[str, Any]]) -> ModelDecision:
        ...


class ToolExecutor(Protocol):
    def execute(self, name: str, arguments: dict[str, Any]) -> str:
        ...


class AgentHarness:
    def __init__(
        self,
        model_client: ModelClient,
        tool_executor: ToolExecutor,
        budget: RuntimeBudget | None = None,
    ) -> None:
        self.model_client = model_client
        self.tool_executor = tool_executor
        self.budget = budget or RuntimeBudget()

    def run(self, user_input: str) -> AgentState:
        state = AgentState(
            run_id=str(uuid.uuid4()),
            user_input=user_input,
            messages=[{"role": "user", "content": user_input}],
        )
        started_at = time.monotonic()

        while state.status == AgentStatus.RUNNING:
            if state.step_index >= self.budget.max_steps:
                state.status = AgentStatus.FAILED
                state.last_error = "max_steps_exceeded"
                break

            if state.tool_calls >= self.budget.max_tool_calls:
                state.status = AgentStatus.FAILED
                state.last_error = "max_tool_calls_exceeded"
                break

            elapsed = time.monotonic() - started_at
            if elapsed >= self.budget.max_elapsed_seconds:
                state.status = AgentStatus.FAILED
                state.last_error = "max_elapsed_seconds_exceeded"
                break

            state.step_index += 1
            logger.info("run_id=%s step=%s status=%s", state.run_id, state.step_index, state.status)

            try:
                decision = self.model_client.decide(state.messages)
            except Exception as exc:
                logger.exception("model_call_failed")
                state.status = AgentStatus.FAILED
                state.last_error = f"model_call_failed: {exc}"
                break

            if decision.final_answer:
                state.messages.append({"role": "assistant", "content": decision.final_answer})
                state.final_answer = decision.final_answer
                state.status = AgentStatus.COMPLETED
                break

            if not decision.tool_call:
                state.status = AgentStatus.FAILED
                state.last_error = "model_returned_neither_answer_nor_tool"
                break

            state.tool_calls += 1

            try:
                observation = self.tool_executor.execute(
                    decision.tool_call.name,
                    decision.tool_call.arguments,
                )
            except Exception as exc:
                logger.exception("tool_execution_failed")
                observation = f"TOOL_ERROR: {exc}"

            state.messages.append(
                {
                    "role": "assistant",
                    "content": None,
                    "tool_call": {
                        "name": decision.tool_call.name,
                        "arguments": decision.tool_call.arguments,
                    },
                }
            )
            state.messages.append(
                {
                    "role": "tool",
                    "name": decision.tool_call.name,
                    "content": observation,
                }
            )

        return state
```

## 设计点评

### 1. 状态与预算分离
`AgentState` 负责“当前发生了什么”，`RuntimeBudget` 负责“最多允许发生多少”。这种分离有利于测试和扩展。

### 2. 模型与执行器解耦
`ModelClient` 和 `ToolExecutor` 通过 `Protocol` 抽象，使 harness 不依赖具体厂商 SDK。

### 3. 所有失败都进入状态
失败不是简单抛异常退出，而是会被记录到 `last_error` 中，便于后续评测与定位。
