## 概述
没有可观测性，就没有可调试的 Agent；没有评测，就没有可比较的 Agent。Harness Engineering 的后半部分，实质上是在回答两个问题：

1. 当前系统到底做了什么。
2. 当前系统到底做得好不好。

## 可观测性的目标

### 1. 还原每一步决策
系统需要记录每一步输入、模型输出、工具调用、tool observation、预算变化和最终状态。

### 2. 区分错误来源
回答失败时，要能区分是上下文装配错误、模型推理错误、工具执行错误还是记忆召回错误。

### 3. 支持回放
一次失败运行应能被完整复现，便于定位问题和验证修复。

## 观测数据通常包括什么
- **日志（Logs）**：离散事件记录，例如“调用了哪个工具”“工具是否超时”。
- **指标（Metrics）**：可聚合数值，例如成功率、平均步数、工具调用次数、延迟分布。
- **链路追踪（Traces）**：把一次完整运行串起来，看到步骤与步骤之间的因果关系。
- **快照（Snapshots）**：保存中间状态，便于回放和调试。

## 评测的目标

### 1. 离线评测
在固定测试集上比较不同 harness 策略、模型版本、提示模板和工具配置。

更系统的离线评测结构可参考 [[Harness Engineering/子专题/01_Evaluation Harness#离线评测的基本结构|Evaluation Harness]]。

### 2. 在线评测
观察生产环境中的真实表现，例如任务完成率、人工接管率、错误恢复率。

### 3. 面向过程评测
不仅看最终答案对不对，也要看中间过程是否合理，例如是否调用了正确工具、是否遵守安全策略。

## 常见评测指标
- **Task Success Rate**：任务最终完成比例。
- **Tool Precision**：工具调用是否必要、是否正确。
- **Step Efficiency**：完成任务的平均步数。
- **Latency**：总耗时、模型耗时、工具耗时。
- **Recovery Rate**：遇到异常后成功恢复的比例。
- **Policy Violation Rate**：越权调用、敏感信息泄漏、非法参数比例。

## 回放与复现实验
一个成熟的 harness 通常支持把一次运行导出为：
- 初始用户输入
- 系统提示与开发者提示
- 召回记忆
- 模型响应
- 工具调用序列
- 最终输出

这样可以做到“问题复现不依赖线上环境重跑”。

## 规范实现示例
下面给出一个结构化日志与 trace 记录示例。真实项目中可以接入 OpenTelemetry、Langfuse、Arize Phoenix 或自建追踪系统。

```python
from __future__ import annotations

import json
import logging
import time
import uuid
from dataclasses import dataclass, asdict


logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("agent_harness")


@dataclass(slots=True)
class StepTrace:
    run_id: str
    step_index: int
    phase: str
    tool_name: str | None
    latency_ms: float
    ok: bool
    detail: dict


class TraceRecorder:
    def __init__(self) -> None:
        self.run_id = str(uuid.uuid4())

    def record(self, trace: StepTrace) -> None:
        logger.info(json.dumps(asdict(trace), ensure_ascii=False))


def observe_phase(
    recorder: TraceRecorder,
    step_index: int,
    phase: str,
    fn,
    *,
    tool_name: str | None = None,
):
    started = time.perf_counter()
    try:
        result = fn()
    except Exception as exc:
        recorder.record(
            StepTrace(
                run_id=recorder.run_id,
                step_index=step_index,
                phase=phase,
                tool_name=tool_name,
                latency_ms=(time.perf_counter() - started) * 1000,
                ok=False,
                detail={"error": str(exc)},
            )
        )
        raise

    recorder.record(
        StepTrace(
            run_id=recorder.run_id,
            step_index=step_index,
            phase=phase,
            tool_name=tool_name,
            latency_ms=(time.perf_counter() - started) * 1000,
            ok=True,
            detail={"result_preview": str(result)[:200]},
        )
    )
    return result
```

## 设计点评

### 1. 观测粒度到“步骤”
只记录最终答案不足以分析 Agent。至少要把模型调用和工具调用拆成独立 phase。

### 2. 日志结构化
用 JSON 记录比纯文本更适合后续聚合统计和可视化。

### 3. 结果预览而不是全量落盘
日志中保存结果摘要，避免把敏感 observation 直接写进长久存储。

## 线上监控
生产环境通常至少监控以下指标：
- 每日运行次数
- 成功率与失败率
- 平均总耗时
- 平均工具调用次数
- 高风险工具调用频次
- 审批触发率
- 人工接管率
