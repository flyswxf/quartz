## 什么是 Agent
Agent（智能体）是指能够感知环境、进行决策并执行动作的计算实体。在基于大语言模型（LLM）的上下文中，Agent 是一种以 LLM 为大脑，具备感知、记忆、思考和行动能力的智能系统。它不仅能生成文本，还能通过调用工具与外部世界交互，解决复杂问题。

核心公式表示为：
$$Agent = LLM + Planning + Memory + Tool Use$$

## 核心架构
Agent 的架构通常包含四个核心组件：
1. **大模型（大脑）**：负责自然语言理解、逻辑推理、决策制定。
2. **[[规划(Planning)#任务分解|规划]]（Planning）**：将复杂任务分解为可管理的子任务，并制定执行步骤。
3. **[[记忆(Memory)#记忆类型|记忆]]（Memory）**：存储上下文和历史信息，分为短期记忆和长期记忆。
4. **[[工具调用(Action)#完整执行生命周期|工具调用]]（Tool Use / Action）**：允许 Agent 访问外部 API、执行代码或查询数据库。

在工程实现中，上述能力通常不是直接堆叠，而是由 [[Harness Engineering/01_概述与设计目标#核心定义|Harness Engineering]] 统一组织成一个可运行的执行系统。

## 为什么需要 Agent
传统 LLM 存在以下局限性，而 Agent 能够解决这些问题：
- **知识滞后**：LLM 的知识停留在训练数据截止日期。Agent 可以通过搜索工具获取实时信息。
- **幻觉问题**：LLM 容易生成看似合理但错误的内容。Agent 可以通过工具验证信息。
- **无法执行操作**：LLM 只能生成文本。Agent 可以执行代码、操作软件、调用 API 完成实际任务。
- **上下文窗口限制**：Agent 可以通过长期记忆系统（如向量数据库）突破上下文限制。

## 典型工作流
1. **感知（Perception）**：接收用户输入或环境反馈。
2. **思考（Brain/Thinking）**：LLM 根据目标和记忆进行推理。
3. **行动（Action）**：决定调用何种工具或输出结果。
4. **观察（Observation）**：获取行动结果，可能触发下一轮思考。

在真实应用中，这一工作流通常由 [[Harness Engineering/02_运行时循环与状态机#运行时循环的最小闭环|运行时循环]] 驱动，而不是单次函数调用完成。
