# 混合精度训练 (Mixed Precision Training)

混合精度训练是一种在深度学习训练中，结合使用单精度（FP32）和半精度（FP16 或 BF16）浮点数的技术，旨在**减少显存占用并加速训练**，同时保持模型精度。

## 一、核心思想

默认情况下，PyTorch 使用 FP32（32位浮点数）进行模型的计算和存储。混合精度训练的核心思路是：
1. **使用 FP16/BF16 进行前向和反向传播**：大多数深度学习操作（如卷积、线性层）对精度不敏感，使用半精度可以使显存占用减半，同时利用 GPU 的 Tensor Cores 大幅提升计算速度。
2. **保留 FP32 的主权重（Master Weights）**：在优化器更新参数时，如果直接使用半精度更新，可能会因为学习率过小导致梯度下溢（Underflow），即数值变成 0。因此，在内存中保留一份 FP32 的模型权重副本，专门用于参数更新。
3. **梯度缩放（Gradient Scaling）**：仅在使用 FP16 时需要。为了防止反向传播时 FP16 的梯度下溢，在反向传播前将 Loss 乘以一个大常数（Scale Factor），放大梯度；在更新参数前，再将梯度除以该常数还原。

## 二、深入理解：FP32 主权重 & 梯度缩放

### 1. 为什么需要 FP32 主权重？

问题出在**优化器更新参数**的环节。以 SGD 为例，权重更新公式为：

$$w_{t+1} = w_t - \eta \cdot g_t$$

其中 $\eta$ 是学习率，$g_t$ 是梯度。当使用 FP16 存储权重时，会遇到精度不足的问题。

**具体例子**：假设权重 $w_t = 1.0$，学习率 $\eta = 10^{-5}$，梯度 $g_t = 0.01$，则理论更新量：

$$\Delta w = \eta \cdot g_t = 10^{-5} \times 0.01 = 10^{-7}$$

理论上更新后 $w = 1.0 - 0.0000001 = 0.9999999$。但 **FP16 的有效精度只有约 3~4 位有效数字**（尾数 10 bit），它能表示的最接近 1.0 的下一个是：

$$1.0 + 2^{-10} \approx 1.00098$$

即 $10^{-7}$ 级别的变化量在 FP16 中**完全无法表示**，直接被截断为 0，权重没有更新——模型"学不动"了。

**解决方案**：在内存中额外保留一份 FP32 精度的权重副本（Master Weights），优化器在这份高精度副本上执行参数更新：

```
前向/反向传播：使用 FP16 模型权重 → 节省显存、加速计算
优化器更新：  使用 FP32 主权重   → 保证更新精度
更新后：      将 FP32 主权重转回 FP16 → 同步到模型
```

$$w_{\text{FP32}} \xrightarrow{\text{cast}} w_{\text{FP16}} \xrightarrow{\text{forward/backward}} g_{\text{FP16}} \xrightarrow{\text{cast}} w_{\text{FP32}} - \eta \cdot g_{\text{FP32}}$$

### 2. 为什么需要梯度缩放？

FP16 的表示范围比 FP32 **窄得多**：

| 格式 | 最小正正规数                  | 最大值                       |
| ---- | ----------------------------- | ---------------------------- |
| FP32 | $\approx 1.2 \times 10^{-38}$ | $\approx 3.4 \times 10^{38}$ |
| FP16 | $\approx 6.1 \times 10^{-5}$  | $65504$                      |
| BF16 | $\approx 1.2 \times 10^{-38}$ | $\approx 3.4 \times 10^{38}$ |

反向传播中梯度往往很小（如 $10^{-7}$）。FP32 可以正常表示，但 FP16 中**低于 $6.1 \times 10^{-5}$ 的值会被 flush to zero（下溢为 0）**，梯度消失，训练失败。

**具体例子**：某个参数梯度 $g = 3.0 \times 10^{-5}$，因为 $3.0 \times 10^{-5} < 6.1 \times 10^{-5}$，直接在 FP16 中下溢为 0。

**解决方案**：三步缩放

1. **缩放 Loss**：反向传播前将 Loss 乘以大常数 $S$（Scale Factor，通常从 $2^{16} = 65536$ 开始）：

$$\text{scaled\_loss} = S \times \text{loss}$$

2. **反向传播**：链式法则使所有梯度被同步放大 $S$ 倍：

$$\tilde{g} = S \cdot g = 65536 \times 3.0 \times 10^{-5} \approx 1.97$$

$\tilde{g} = 1.97$ 远大于 FP16 最小值，不会下溢。

3. **还原梯度**：优化器更新前，在 FP32 精度下将梯度除以 $S$ 还原：

$$g = \frac{\tilde{g}}{S} = \frac{1.97}{65536} \approx 3.0 \times 10^{-5}$$

### 3. Scale Factor 的动态调整

`GradScaler` 不使用固定的 $S$，而是动态调整：

- 每隔 N 步（默认 2000 步），尝试将 $S$ 乘以 2（增大缩放），看是否出现 `inf`/`nan`
- 如果出现 `inf`/`nan`，说明缩放过头导致**上溢**，则跳过本步更新，将 $S$ 除以 2

```
S = 65536 → 训练正常 → S = 131072 → 出现 inf → 跳过更新 → S = 65536
```

### 4. BF16 为什么不需要梯度缩放？

回到上面的表格：BF16 的最小正正规数 $\approx 1.2 \times 10^{-38}$，与 FP32 **完全相同**！FP32 能表示的小梯度，BF16 也都能表示，根本不会下溢，因此直接省去 `GradScaler` 即可。

### 总结

| 机制        | 解决的问题                       | 适用场景             |
| ----------- | -------------------------------- | -------------------- |
| FP32 主权重 | 优化器更新量太小被 FP16 截断为 0 | FP16 和 BF16（保险） |
| 梯度缩放    | 反向传播梯度太小被 FP16 下溢为 0 | **仅 FP16**          |

## 三、PyTorch 使用

PyTorch 提供了原生的 `torch.amp` (Automatic Mixed Precision) 模块来实现这一功能。

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.amp import autocast, GradScaler

# 1. 初始化模型和优化器
model = nn.Linear(1024, 1024).cuda()
optimizer = optim.Adam(model.parameters(), lr=1e-3)

# 2. 初始化 GradScaler (如果使用 BF16，通常不需要 Scaler，只有 FP16 需要)
scaler = GradScaler('cuda')

for data, label in dataloader:
    data, label = data.cuda(), label.cuda()
    optimizer.zero_grad()
    
    # 3. 使用 autocast 上下文管理器，自动开启半精度前向传播
    with autocast('cuda', dtype=torch.float16):
        output = model(data)
        loss = criterion(output, label)
        
    # 4. 梯度缩放并反向传播
    scaler.scale(loss).backward()
    
    # 5. 更新参数并更新缩放因子
    scaler.step(optimizer)
    scaler.update()
```

## 四、关键要点说明

- **FP16 与 BF16 的选择**：
  - **FP16**：精度较高，但表示范围较窄，容易出现溢出（Overflow/Underflow），必须配合 `GradScaler` 使用。
  - **BF16 (BFloat16)**：表示范围与 FP32 相同，但精度较低。由于范围广，**极少出现溢出问题，不需要使用 `GradScaler`**。仅在 Ampere 架构及以上的 GPU（如 RTX 30 系列、A100）支持。
- **操作白名单与黑名单**：`autocast` 并不是把所有操作都转为半精度。例如，矩阵乘法、卷积会自动转为半精度；但 Softmax、LayerNorm 等对数值稳定性要求极高的操作，会强制保留为 FP32。
- **显存优化效果**：虽然理论上数据占用的显存减半，但由于需要保存 FP32 的主权重和优化器状态，整体显存通常只能节省 30% ~ 40% 左右，并非绝对的减半。
