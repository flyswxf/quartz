# 2_形状与维度变换

## 核心思想
在深度学习中，不同的网络层（如卷积层、全连接层、注意力机制）对输入 Tensor 的维度排布有着严格的要求。形状与维度变换操作能够在**不改变底层数据内容**的前提下，重新排列和重塑 Tensor 的视图或内存，使得数据能与网络计算对齐。

## PyTorch 实现/使用

```python
import torch

tensor = torch.arange(24) # [0, 1, ..., 23]

# 1. 重塑形状: view 和 reshape
t_view = tensor.view(2, 3, 4)       # 变为 2x3x4，要求内存连续
t_reshape = tensor.reshape(2, 3, 4) # 变为 2x3x4，必要时自动拷贝数据

# 2. 增加或移除单维度: unsqueeze 和 squeeze
t_unsq = t_view.unsqueeze(0)        # 在第 0 维增加，变为 1x2x3x4
t_sq = t_unsq.squeeze(0)            # 移除第 0 维，恢复为 2x3x4

# 3. 维度交换: transpose (通常用于 2 个维度的交换)
t_trans = t_view.transpose(0, 1)    # 交换第 0 维和第 1 维，变为 3x2x4

# 4. 多维重排: permute (常用于通道转换，如 [B, C, H, W] 转 [B, H, W, C])
t_perm = t_view.permute(0, 2, 1)    # 原来索引 0,1,2 重新排成 0,2,1，变为 2x4x3

# 5. 展平: flatten
t_flat = t_view.flatten(start_dim=1) # 从第 1 维展平到最后，变为 2x12
```

## 底层原理：视图 (View) 与内存连续性 (Contiguous)

### 1. PyTorch 视图功能的底层实现
PyTorch 的 Tensor 实际上由两部分组成：
1. **Storage (存储区)**：一块一维的、连续的物理内存数组，真正存放数据的地方。
2. **Metadata (元数据)**：描述如何解析这块物理内存的“头信息”，主要包含 `shape` (形状)、`stride` (步长) 和 `offset` (偏移量)。

**步长 (Stride)** 的定义是：在某一个维度上，移动到下一个元素需要跨越的底层一维内存元素的个数。
对于多维张量，访问索引 $(i, j, k)$ 对应的物理内存地址公式为：
$$ \text{物理地址偏移量} = i \times \text{stride}[0] + j \times \text{stride}[1] + k \times \text{stride}[2] $$

**视图 (View) 的本质**：当调用 `.view()` 操作时，PyTorch **完全不会去移动或复制底层的物理内存数据**，而是仅仅创建了一个新的 Metadata 头（修改了 `shape` 和 `stride`），让它指向同一块 Storage。因为没有数据拷贝，视图操作的速度极快。

### 2. 维度交换为什么会导致内存不连续？
**内存连续 (Contiguous)** 的定义是：按照张量的形状从左到右遍历所有元素时，它们在底层一维物理内存中的地址也是相邻的（即最内层维度的 `stride` 为 1，且每个维度的 `stride` 等于其后所有维度大小的乘积）。

**维度交换导致不连续的例子**：
假设创建一个形状为 `(2, 3)` 的张量：
```python
t = torch.arange(6).view(2, 3)
```
- 底层 Storage 为：`[0, 1, 2, 3, 4, 5]`
- 元数据为：`shape = (2, 3)`, `stride = (3, 1)`（换行需跨越3个元素，同行下一个只需跨越1个）
此时内存是**连续的**。

如果执行维度交换 `t_trans = t.transpose(0, 1)`：
- PyTorch 仅仅是简单粗暴地交换了元数据中的对应值。
- 新的元数据变为：`shape = (3, 2)`, `stride = (1, 3)`。
- 底层 Storage **没有任何变化**，依旧是 `[0, 1, 2, 3, 4, 5]`。

**为什么此时不连续了？**
在新的 `t_trans` 视角下，沿着最后一行（最内层维度，即列）移动到下一个元素时，由于当前的 `stride[1] = 3`，在物理内存上需要一次性跳跃 3 个元素的位置（比如从 `0` 跳到 `3`）。物理内存的读取变成了“跳跃式”的，不再是一个挨着一个排列，因此张量被标记为**内存不连续 (non-contiguous)**。

由于 `view()` 操作严格依赖底层内存的物理连续性才能推导出合法的数学映射，所以对不连续的张量调用 `view()` 会报错。必须先调用 `.contiguous()`——该操作会强制开辟一块全新的物理内存，把数据按照新的顺序连续地复制过去，并重新生成 `stride`，之后才能再次使用 `view()`。

## 关键要点说明
- **`view` vs `reshape`**：`view` 操作仅改变张量的视图，速度极快，但前提是原 Tensor 必须在内存中是连续的（contiguous）。如果经过了 `transpose` 等操作导致内存不再连续，调用 `view` 会报错。而 `reshape` 更加安全，它在内存连续时表现如 `view`，在不连续时会自动深拷贝生成一个新的连续 Tensor。
- **`unsqueeze` 与广播机制**：在执行矩阵加法等运算时，经常需要通过 `unsqueeze(dim)` 扩展某个维度为 1，从而利用 PyTorch 的广播机制（Broadcasting）完成运算，而无需手动复制数据。
- **`permute` 后必须 `contiguous()`**：使用 `transpose` 或 `permute` 交换维度后，Tensor 的内存分布不再连续。如果在后面紧跟 `view()` 操作，必须先调用 `.contiguous()`：`tensor.permute(...).contiguous().view(...)`。
