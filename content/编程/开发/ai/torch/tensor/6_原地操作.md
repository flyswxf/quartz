# 6_原地操作

## 核心思想
在处理规模庞大的 Tensor（如大语言模型的参数或超大 Batch 的图像）时，内存/显存是一种极为珍贵的资源。PyTorch 提供了一系列“原地操作（In-place Operations）”，它们直接在 Tensor 原有分配的内存地址上修改数值，从而避免创建新 Tensor 带来的额外内存开销。

## PyTorch 实现/使用

在 PyTorch 的 API 命名规范中，**任何以一个下划线 `_` 结尾的方法**，都表示该方法是原地操作。

```python
import torch

# 创建一个 2x2 的全 1 张量
t = torch.ones(2, 2)
print("初始 t:\n", t)

# 1. 原地加法: add_()
t.add_(5)
# 此时 t 自身的数据已经被修改为全 6，没有生成新的 tensor
print("原地加 5 后:\n", t)

# 2. 原地填充: fill_()
t.fill_(0)
# t 被原地重置为全 0
print("原地填充 0 后:\n", t)

# 3. 原地清零: zero_()
t.zero_()
# 等价于 t.fill_(0)，常用于优化器清零梯度 optimizer.zero_grad() 中对参数梯度的清理

# 4. 原地随机初始化
t.normal_(mean=0, std=1) # 原地替换为正态分布随机数
t.uniform_(-1, 1)        # 原地替换为均匀分布随机数
```

## 关键要点说明
- **内存优化**：在模型推理（Inference）阶段或者确定不需要求导的场景中，尽可能使用原地操作（如 `x.add_(y)` 代替 `x = x + y`，或者在使用激活函数时指定 `nn.ReLU(inplace=True)`）可以有效降低显存峰值占用。
- **与反向传播的冲突**：如果在网络的前向传播中（需要求导 `requires_grad=True`），对参与后续梯度计算的中间变量执行了原地修改，PyTorch 的自动求导引擎 (Autograd) 往往会抛出错误：`RuntimeError: one of the variables needed for gradient computation has been modified by an inplace operation`。这是因为反向传播需要用到历史原始值，而它已经被覆盖了。
- **安全做法**：在写 `forward` 函数时，除非非常清楚某个变量的旧值绝不会被反向传播用到，否则尽量少用原地操作。而在模型权重初始化阶段（如 `nn.init.constant_(layer.weight, 0)`），因为不需要求导历史，所以广泛使用 `_` 原地方法。
