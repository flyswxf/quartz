## 数据为什么决定上限
预训练最核心的资源不是某个技巧，而是数据分布本身。模型参数只能压缩它见过的统计规律，因此语料的覆盖度、多样性、质量和重复率，会直接决定模型能形成什么能力。

一个很实用的判断是：
- 参数量决定能装多少。
- 数据质量决定装进去的是不是有用。
- 数据配比决定最终偏向哪类能力。

## 数据来源
常见语料来源包括：
- 网页文本：覆盖广，但噪声高。
- 书籍与百科：结构较完整，语言质量高。
- 代码仓库：提升代码理解与生成能力。
- 数学与推理语料：提升形式化表达与问题分解能力。
- 对话与问答语料：帮助模型更适应交互式表达，但这类通常更常见于[[../微调方法/2_监督微调（SFT）|SFT]]阶段。

实际中经常会把通用文本、代码、数学、专业领域语料混合训练，通过配比控制能力侧重。

## 数据清洗
### 去重
重复样本会让模型以为某些模式频率远高于真实世界，造成记忆偏置，也会浪费 token 预算。常见做法包括精确去重、近似去重、段落级 MinHash 去重。

### 质量过滤
低质量文本常表现为乱码、模板页、广告页、无结构复制文本、机器生成污染。过滤目标不是追求绝对干净，而是尽量提高单位 token 的信息密度。

### 安全与合规
数据可能包含隐私、版权风险、个人信息、敏感内容。实际项目中，合规处理往往与建模本身同等重要。

## 分词器为什么重要
语言模型不是直接处理词或字，而是处理 token。分词器会把原始文本映射成离散 token 序列，直接影响：
- 序列长度。
- 表达粒度。
- 稀有词拆分方式。
- 训练和推理成本。

如果某种语言或某类符号在分词器中被切得很碎，那么同样一段内容会消耗更多 token，训练难度也会更高。

### 常见分词方法
- BPE：通过频率合并子词，工程上非常常见。
- Unigram：从候选子词集合中选择更优分解。
- WordPiece：与 BPE 思想接近，常用于早期 NLP 模型。

### 分词器与模型能力的关系
- 代码模型通常希望对缩进、标点、关键字有良好切分。
- 中文场景下，字符级与子词级切分会显著影响 token 效率。
- 数学和公式场景中，如果符号被切得过细，训练难度会上升。

因此，模型结构不变但分词器改了并不是小改动，往往会显著影响训练稳定性和数据效率。

## 数据配比
假设训练集由通用文本、代码、数学三部分组成：
$$
\mathcal{D} = \alpha \mathcal{D}_{\text{text}} + \beta \mathcal{D}_{\text{code}} + \gamma \mathcal{D}_{\text{math}}, \quad \alpha + \beta + \gamma = 1
$$
其中 $\alpha, \beta, \gamma$ 代表采样比例。提高某一类数据的比例，通常会增强该方向能力，但也会挤占其他能力的训练机会。

### 配比的常见取舍
- 通用文本比例高：语言自然度更好，泛化更稳。
- 代码比例高：代码生成更强，但自然语言聊天风格可能变硬。
- 数学比例高：形式推理可能更强，但开放域表达可能受影响。
- 领域语料比例过高：领域内更准，但有更高的灾难性偏移风险。

## Token 不是越多越好
大量低质量数据并不一定优于较少的高质量数据。若重复率高、信息密度低、噪声大，模型会把预算浪费在无效统计上。

更准确的说法是：应尽可能提高有效 token 密度。这也是为什么高质量继续预训练有时能明显改善某个领域表现，见[[3_预训练过程、扩展定律与继续预训练#继续预训练（Continued Pretraining）|继续预训练]]。

## 数据污染问题
### 评测集污染
如果训练语料包含评测题答案，离线分数会虚高，无法反映真实泛化能力。

### 生成数据污染
当互联网上机器生成内容越来越多时，后续预训练很可能把旧模型输出再次吃进去，形成模型喂模型的闭环。这样会降低多样性，并放大早期错误分布。

## 一个常见误区
很多人会把效果不佳归因于模型规模不够，但在相同预算下，导致问题的根源经常是：
- 数据分布不对。
- 去重和清洗不足。
- 分词器不适配。
- 领域数据配比失衡。

如果这些问题没处理好，即使后面做[[../微调方法/2_监督微调（SFT）|SFT]]或[[../微调方法/3_参数高效微调：LoRA、QLoRA 与 Adapter|LoRA]]，效果也可能只是在坏底座上做局部修补。
