## 训练流程
一个完整的预训练流程通常包含：
1. 构建语料与分词器，见[[2_预训练数据、分词与数据配比#分词器为什么重要|分词器]]。
2. 设计模型规模，包括参数量、层数、隐藏维度、上下文长度。
3. 设定优化器、学习率、batch size、训练 token 数。
4. 做大规模分布式训练，持续监控 loss、吞吐、稳定性。
5. 训练结束后做基础评测，再决定是否进入[[../微调方法/2_监督微调（SFT）|SFT]]或继续预训练。

## 训练中的关键超参数
### 学习率
学习率过大容易震荡或发散，过小则训练过慢。预训练常见 warmup + cosine decay 或类似调度策略。

### 全局 batch size
更大的全局 batch 通常带来更稳定的梯度估计，但也要求更强算力与更细致的学习率匹配。

### 上下文长度
上下文长度越长，模型越能利用长依赖，但训练成本通常接近二次增长，特别是在全注意力结构下。

### Token 预算
最终训练效果经常更适合用看过多少 token来衡量，而不是训练了多少 epoch。因为互联网语料极大，很多预训练本来就不是传统意义上的有限轮数训练。

## 扩展定律（Scaling Laws）
扩展定律讨论的是：在固定或变化的预算下，参数量 $N$、数据量 $D$、计算量 $C$ 如何共同影响损失。经验上，经常可以观察到幂律关系：
$$
L(N, D, C) \approx A N^{-\alpha} + B D^{-\beta} + E
$$
这说明：
- 增大模型规模通常能降低损失。
- 增加高质量数据通常也能降低损失。
- 但收益会递减，不存在无限线性回报。

### Chinchilla 风格结论
后续研究强调：很多模型不是参数太少，而是训练 token 不够。也就是说，在固定算力下，较小但训练更充分的模型，可能优于较大但训练不足的模型。

这一点对项目决策很关键，因为它意味着：
- 盲目追大模型不一定划算。
- 如果数据和算力允许，更好的 token/parameter 匹配可能更重要。

## 继续预训练（Continued Pretraining）
继续预训练指的是：拿一个已经完成基础预训练的模型，在新语料上继续做语言建模训练。常见形式有：
- Domain Adaptive Pretraining：面向法律、医疗、金融、代码等领域。
- Language Adaptive Pretraining：面向新语种或低资源语种。
- Task-style Continued Pretraining：虽然目标仍是语言建模，但语料分布更接近后续任务。

### 为什么继续预训练有效
如果基础模型没在某个领域见过足够多的数据，那么直接做[[../微调方法/2_监督微调（SFT）|SFT]]往往只是教会回答样子，不一定补上底层知识。继续预训练更像先补底座，再做行为塑形。

### 什么时候优先继续预训练
- 领域术语密集，基础模型明显不懂。
- 领域文本长、结构特殊，与通用网络文本差异很大。
- 希望提升的是理解和知识覆盖，而不是单纯输出格式。

### 风险
继续预训练如果数据过窄，可能导致分布偏移过大，损伤通用能力。这与[[../工程实践/1_数据构造、评测与过拟合排查#领域数据比例过高时容易发生什么|领域过拟合]]密切相关。

## 训练稳定性问题
### Loss 震荡
常见原因包括学习率过大、梯度爆炸、混合精度不稳定、数据质量波动。

### 训练崩溃
表现为 `nan`、`inf` 或 loss 直接飞掉。通常需要检查初始化、梯度裁剪、混合精度设置、异常样本。

### 吞吐下降
可能来自数据管道瓶颈、通信开销、上下文过长、显存碎片。可参考[[../工程实践/2_训练配置、显存与吞吐优化#吞吐优化的核心思路|吞吐优化]]。

## 预训练完成后看什么
- 验证集 loss / PPL 是否持续改善。
- 通用基准和领域基准是否同步改善。
- 长上下文、代码、数学等重点能力有没有塌陷。
- 是否出现明显记忆化、重复输出或异常偏置。

## 与微调的衔接
预训练结束后，下一步不一定总是[[../微调方法/2_监督微调（SFT）|SFT]]。一个更合理的判断顺序是：
1. 先确认模型缺的是知识分布，还是行为格式。
2. 如果缺知识分布，优先继续预训练。
3. 如果已有知识但不听指令，优先 SFT。
4. 如果会答但质量排序不稳定，再做[[../微调方法/4_偏好对齐：RLHF、PPO 与 DPO|偏好对齐]]。
