## 1. 核心概念：什么是 NPM？

**NPM (Node Package Manager)** 是 Node.js 的包管理工具，也是前端工程化的基石。它不仅仅是一个下载库的工具，更是现代前端项目的**任务指挥中心**。

> [!INFO] 核心文件：`package.json`
> 每个项目的根目录下都有一个 `package.json` 文件，它是项目的“身份证”和“说明书”。它定义了：
> - **项目元数据**：名称、版本、作者。
> - **依赖包 (Dependencies)**：项目运行所需的第三方库（如 React）。
> - **脚本 (Scripts)**：项目能执行的命令（如启动、打包）。

## 2. 开发环境 vs 生产环境

在现代前端开发中，我们严格区分**开发环境 (Development)** 和 **生产环境 (Production)**。

| 特性 | 开发环境 (Development) | 生产环境 (Production) |
| :--- | :--- | :--- |
| **命令** | `npm run dev` | `npm run build` |
| **目标** | **开发体验** (DX) | **用户体验** (UX) & 性能 |
| **代码状态** | 未压缩，保留空格和注释 | 极致压缩，混淆变量名 |
| **调试** | 有详细的错误提示，支持 Source Map | 去除所有 `console.log` 和调试信息 |
| **加载方式** | 模块热替换 (HMR)，修改代码立即生效 | 浏览器缓存优化，文件指纹 (Hash) |
| **产物位置** | 内存中 (不生成实体文件) | `dist/` 目录 (生成实体文件) |

### 🛠️ 开发模式 (`npm run dev`)
- **热更新 (HMR)**：当你按下 `Ctrl+S` 保存代码时，浏览器会自动刷新或局部替换修改的模块，无需手动刷新页面。
- **源码映射 (Source Map)**：即使浏览器运行的是编译后的代码，报错时依然能定位到你写的 TypeScript 源码位置。

### 🚀 生产模式 (`npm run build`)
- **代码压缩 (Minification)**：将 `function longName() {}` 压缩为 `function a(){}`，删除空格和换行，减小文件体积。
- **摇树优化 (Tree Shaking)**：像摇晃一棵树一样，把代码中“枯死”（未被引用）的叶子（函数/变量）摇掉，只打包用到的代码。
- **兼容性处理**：将最新的 TypeScript/ES6+ 语法转换为浏览器能广泛支持的 JavaScript 版本。

## 3. 常用命令详解

在你的终端 (Terminal) 中，这几个命令是最常用的：

### `npm install` (或 `npm i`)
*   **作用**：根据 `package.json` 下载所有依赖包到 `node_modules` 目录。
*   **场景**：刚下载完项目，或者新加了依赖时使用。

### `npm run dev`
*   **作用**：启动本地开发服务器（通常是 Vite 或 Webpack）。
*   **场景**：日常写代码时一直开着。

### `npm run build`
*   **作用**：执行构建流程，生成最终的网站文件。
*   **场景**：准备发布上线前，或者想看看最终打包大小。
*   **产物**：生成的 `dist` 文件夹包含了所有静态资源（HTML, CSS, JS），这些文件可以直接部署到 Nginx、Vercel 或 GitHub Pages。

### `npm run preview`
*   **作用**：在本地启动一个服务器，模拟生产环境运行 `dist` 目录下的代码。
*   **场景**：`build` 完之后，用来检查打包后的网站是否正常运行（比如检查有没有资源路径错误）。

## 4. 为什么浏览器不能直接运行源码？

你可能会问：*“我写的也是 JS/TS，为什么浏览器不能直接跑，非要 Build？”*

1.  **TypeScript 浏览器不认识**：浏览器只能运行 JavaScript，必须通过编译将 `.ts` 转为 `.js`。
2.  **模块化差异**：虽然现代浏览器支持 ES Modules，但为了性能（减少 HTTP 请求数），我们通常还是会将几百个小文件打包成几个大文件（Bundle）。
3.  **JSX 语法**：React 的 `<Component />` 写法本质是语法糖，浏览器无法解析，需要工具转译成 `React.createElement`。
4.  **性能优化**：手写的代码为了可读性会有大量空格、长变量名，这对网络传输是浪费。Build 过程会自动帮我们做“瘦身”。

---

> [!TIP] 最佳实践
> - **日常开发**：只用 `npm run dev`。
> - **提交代码前**：建议跑一次 `npm run build` 确保没有编译错误。
> - **部署上线**：服务器上只需要 `dist` 目录的内容，不需要 `node_modules` 和源码。
