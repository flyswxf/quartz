# 软件错误/缺陷/故障/失效

> [!important] 关键要点
> - 外部可见的软件失效是测试中推断软件中存在缺陷的基本方法
> - 没有失效并不代表软件中不存在缺陷
> - 产生失效一定意味着软件有故障，且一定意味着软件存在缺陷
> - 产生故障一定意味着软件存在缺陷
> - 缺陷具有隐蔽性

> [!summary]+ 概念关系速览
> 下图展示从“人为错误”到“缺陷/故障/失效”的因果链：
>
> ```mermaid
> flowchart LR
>   E[Software Error<br/>人为错误] --> D[Software Defect<br/>软件缺陷]
>   D -- 被激活 --> F[Software Fault<br/>内部故障状态]
>   F -- 无适当处理 --> L[Software Failure<br/>外部失效]
> ```
>
## 术语对照表
| 概念               | 中文   | 何时出现          | 体现形式                        | 备注           |
| ---------------- | ---- | ------------- | --------------------------- | ------------ |
| Software Error   | 软件错误 | 软件生存期内（人为活动中） | 不希望/不可接受的人为错误               | 研发人员的错误在过程层面 |
| Software Defect  | 软件缺陷 | 存在于软件静态成品中    | 文档/数据/程序中的偏差（Bug是口语化称呼）     | 可被触发但可能长期潜伏  |
| Software Fault   | 软件故障 | 运行时（内部）       | 不希望/不可接受的内部状态               | 缺陷被激活的直接结果   |
| Software Failure | 软件失效 | 运行时（外部）       | 不希望/不可接受的外部行为（崩溃、闪退、结果不正确等） | 对用户/系统可见     |

## Software Defect（软件缺陷）

^2b8e24

- 存在于软件（文档、数据、程序）之中的那些不希望或不可接受的偏差
- “Bug”是口语化的“缺陷”

## Software Failure（软件失效）
- 软件运行时产生的一种不希望或不可接受的外部行为结果（系统崩溃、闪退、结果不正确……）
> [!warning] 测试中的两条重要结论
> ① 外部可见的软件失效是测试中推断软件中存在缺陷的基本方法
>
> ② 没有失效并不代表软件中不存在缺陷

## Software Fault（软件故障）
- 软件运行过程中出现的一种不希望或不可接受的内部状态
- **内部状态**：由所有程序变量的当前值和程序指针构成的集合
- 记号示例：（x, y, i, pc）
> [!example] 状态示例
> 初始状态: (x = [2,3,5], y = 2, pc: i = x.length - 1)
>
> 执行一步后的状态: (x = [2,3,5], y = 2, i = 2, pc: i > 0) ^612be4
- 故障是缺陷激活的结果；如果缺陷被激活，内部就可能出现故障
- 若无适当处理措施，软件故障很可能会导致软件失效

## Software Error（软件错误）
- 在软件生存期内的不希望或者不可接受的人为错误
- 软件缺陷本质上是研发人员在软件研发过程中所犯错误在软件中的可视化结果

## 关系与推理规则
> [!important]- 折叠：推理规则（必记）
> - 缺陷具有隐蔽性
> - 有缺陷不一定产生故障（可能未被激活）
> - 有故障不一定会失效（可能被异常处理/容错机制屏蔽）
> - 产生失效 ⇒ 一定意味着软件有故障 ⇒ 一定意味着软件存在缺陷
> - 产生故障 ⇒ 一定意味着软件存在缺陷
