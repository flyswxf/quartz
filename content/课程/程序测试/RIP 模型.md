# RIP 模型（Reachability · Infection · Propagation）

> [!important] 关键结论（必须同时满足）
> 缺陷被测试用例“观察到”的必要且充分条件：R ∧ I ∧ P。
> - R 可达性：执行必须到达包含缺陷的语句/位置。
> - I 感染性：执行该位置**之后**，程序的内部状态![[错误#^612be4|内部状态]]必须被“错误地”改变。
> - P 传播性：被感染的内部状态必须向外传播到可观察输出（返回值、异常、UI、日志等）。

> [!summary]+ 模型关系
> ```mermaid
> flowchart LR
>   R[Reachability可达性] --> I[Infection感染性]
>   I --> P[Propagation传播性]
>   P --> Obs[Observable Failure可观察到的失效]
> ```
>
## 三要素对照表
| 要素    | 判断关注点                 | 典型证据                 |
| ----- | --------------------- | -------------------- |
| 可达性 R | 是否真正执行到“缺陷所在语句/分支/条件” | 覆盖数据/路径、断点、日志、覆盖率    |
| 感染性 I | 正确实现与错误实现的内部状态是否产生差异  | 变量值/路径/分支取向不同、断言内部状态 |
| 传播性 P | 内部差异是否影响到对外可观测结果      | 返回值/抛出的异常/输出不同       |

---

## 示例：findLast（Java）
```java
public int findLast (int[] x, int y) {
  // Effects: If x==null throw NullPointerException
  // else return the index of the last element in x that equals y.
  // If no such element exists, return -1
  for (int i = x.length - 1; i > 0; i--) { // 缺陷：应为 i >= 0
    if (x[i] == y) return i;
  }
  return -1;
}
// 期望：当 y 出现在 x[0] 时应返回 0
```

> [!tip] 如何暴露该缺陷
> 让循环必须检查 i==0 位置，并使该检查影响返回结果（即令 y == x[0]）。

### 用例评估（R/I/P）
| 编号  | 输入 (x, y)  | R   | I   | P   | 结果   |
| --- | ---------- | --- | --- | --- | ---- |
| ①   | [2,3,5], 2 | ✓   | ✓   | ✓   | 揭示缺陷 |
| ②   | null, 4    | ✗   | ✗   | ✗   | 不揭示  |
| ③   | [], 4      | ✓   | ✗   | ✗   | 不揭示  |
| ④   | [1,2,4], 4 | ✓   | ✗   | ✗   | 不揭示  |
| ⑤   | [1], 4     | ✓   | ✓   | ✗   | 不揭示  |

> [!info] 逐案说明
> - ① R: 到达 for 头的缺陷处且需检查 i==0；I: 正确与错误实现对边界分支的决策不同；P: 返回值从 0 变为 -1。
> - ② R: 在循环之前抛出 NPE，未到达缺陷行；I/P: 不适用。
> - ③ R: for 头部被执行（即缺陷处被评估）；I: 内部状态无差异；P: 无。
> - ④ R: 缺陷行被执行；I: 执行后状态与正确实现相同（目标在 i=2，缺陷影响的是 i==0 的边界）；P: 无。
> - ⑤ R: 缺陷行被执行；I: 执行后正确代码进入循环,错误代码不进入循环；P: 由于 y 不在数组中，两版本外部结果均为 -1。

> [!example] 最小揭示用例
> - x = [2]，y = 2 或 x = [2,3,5]，y = 2。
> - 这两者都让程序必须在 i==0 处作出与正确实现不同的决策，并把差异传播到返回值。
