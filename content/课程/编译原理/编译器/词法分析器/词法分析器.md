# 词法分析器

词法分析是编译过程的第一个阶段。其主要任务是逐个字符地读取源程序，将其组成逻辑上独立的、有意义的单词（Token），并输出词法单元序列。

### 关键术语
*   **词法单元 (Token)**: 语法分析的基本单位，通常由 `<词法单元名, 属性值>` 组成。例如：`<id, "x">`, `<assign, =>`。
*   **模式 (Pattern)**: 描述一类词法单元的规则。例如：标识符的模式是“以字母开头，后跟零个或多个字母/数字”。
*   **词素 (Lexeme)**: 源程序中匹配某个模式的实际字符序列。例如：`count = 1` 中的 `count`、`=`、`1` 都是词素。

### 示例
语句：`position = initial + rate * 60`
被转化为词法单元序列：
1. `<id, "position">`
2. `<assign, =>`
3. `<id, "initial">`
4. `<op, +>`
5. `<id, "rate">`
6. `<op, *>`
7. `<number, "60">`

## 2. 模式的描述：[[正规式]] (Regular Expression)

词法单元的模式用 [[正规式]] 描述。对于复杂模式，可以使用 [[正规定义]] 进行模块化命名；也可以从 [[正规文法]] 的角度等价描述词法结构。


## 3. 模式的识别：有限自动机 (Finite Automata)
有限自动机（FA）用于识别正规式描述的语言。分为确定的有限自动机（DFA）和非确定的有限自动机（NFA）。

### 3.1 NFA (非确定的有限自动机)
*   **特点**: 对于同一个状态和同一个输入符号，可能存在多个状态转移；允许 $\epsilon$ 转移（不消耗输入字符的转移）。
*   **五元组定义**:
    $$M = (S, \Sigma, \delta, s_0, F)$$
    其中：$S$ 是状态集，$\Sigma$ 是输入字母表，$\delta$ 是转移函数，$s_0$ 是初始状态，$F$ 是接受状态集。

### 3.2 DFA (确定的有限自动机)
*   **特点**: 没有 $\epsilon$ 转移；对于每个状态和每个输入符号，**唯一确定**一个后继状态。

### 3.3 自动机的转换与优化
词法分析器的生成过程通常遵循以下路径：
1.  **[[正规式]] $\to$ NFA**: 使用 **[[Thompson构造法]]**。
2.  **NFA $\to$ DFA**: 使用 **[[子集构造法]]**。
3.  **DFA $\to$ 最小化 DFA**: 使用 **[[Hopcroft 算法]]**。

此外，**[[直接构造法]]** 提供了一条捷径：直接从 [[正规式]] 构造 DFA，跳过中间的 NFA，是 Lex/Flex 等工具实际采用的高效方案。

## 4. 词法错误处理
词法分析器能发现的错误类型非常有限，主要包括：
*   非法字符（当前字符不在字母表中）
*   字符串常量未正确闭合
*   注释未正确闭合

**错误恢复策略**：
*   **恐慌模式 (Panic Mode)**: 丢弃当前字符，直到找到一个合法的起始字符。
