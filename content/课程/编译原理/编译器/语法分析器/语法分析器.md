## 1. 概述

语法分析是编译过程的第二阶段。它的主要任务是：接收词法分析器提供的记号（Token）流，根据语言的语法规则（通常由上下文无关文法描述），构建出一棵[[语法树]]（或抽象语法树 AST），从而检查输入的程序是否符合语法规则。

## 3. 自顶向下分析 (Top-Down Parsing)

从文法的开始符号出发，尝试推导出与输入符号串完全匹配的句子（构建[[语法树]]的过程从根节点到叶节点）。

### 3.1 递归下降分析 (Recursive Descent Parsing)

- 为每个非终结符编写一个递归函数。
- **缺点**：如果文法包含**左递归**（如 $A \to A \alpha$），会导致函数无限循环调用自己。

### 3.2 [[LL(1)分析法]]

LL(1) 分析法是一种不需要回溯的、高效的自顶向下分析方法。

---

## 4. 自底向上分析 (Bottom-Up Parsing)

从输入符号串开始，尝试将其归约（Reduce）为文法的开始符号。通常采用**移进-归约 (Shift-Reduce)** 工作方式。

### 4.1 核心概念：移进-归约

**例子：分析 `id + id`**
假设无二义性文法为：$E \to E + T \mid T$，$T \to \text{id}$

| 步骤 | 符号栈 (Stack) | 剩余输入串 (Input) | 动作 (Action)     | 说明                                          |
| :--- | :------------- | :----------------- | :---------------- | :-------------------------------------------- |
| 1    |                | `id + id`          | **移进 (Shift)**  | 把第一个 `id` 压入栈                          |
| 2    | `id`           | `+ id`             | **归约 (Reduce)** | 用 $T \to \text{id}$ 将栈顶的 `id` 归约为 `T` |
| 3    | `T`            | `+ id`             | **归约 (Reduce)** | 用 $E \to T$ 将 `T` 归约为 `E`                |
| 4    | `E`            | `+ id`             | **移进 (Shift)**  | 把 `+` 压入栈                                 |
| 5    | `E +`          | `id`               | **移进 (Shift)**  | 把第二个 `id` 压入栈                          |
| 6    | `E + id`       |                    | **归约 (Reduce)** | 用 $T \to \text{id}$ 将栈顶的 `id` 归约为 `T` |
| 7    | `E + T`        |                    | **归约 (Reduce)** | 用 $E \to E + T$ 将栈顶的 `E + T` 归约为 `E`  |
| 8    | `E`            |                    | **接受 (Accept)** | 栈里只剩开始符号 `E`，输入串已空，分析成功！  |

### 4.2 LR 分析法

- 依靠状态栈和符号栈进行分析，通过构造 DFA（有限状态自动机）来识别什么时候该进行“归约”。
- **LR 家族**（按分析能力由弱到强）：
  1. **[[LR(0)]]**：闭着眼睛瞎归约（不看下一个 Token）。
  2. **[[SLR(1)]]**：稍微看一眼下一个 Token（利用 `FOLLOW` 集合解决冲突）。
  3. **[[LR(1)]]**：精确计算每个状态下看哪个 Token 才归约，能力最强，但状态机大得吓人。
  4. **[[LALR(1)]]**：合并 LR(1) 中相似的状态，体积缩小，能力依然很强。**Yacc / Bison** 等工具用的就是 LALR(1)。

## 5. 抽象语法树 (Abstract Syntax Tree, AST)

- 语法分析的最终输出通常是 AST，而不是具体的分析树（Parse Tree）。
- AST 去掉了括号等“为了语法规则而存在”的冗余节点，只保留程序的“本质计算结构”。

**例子：`3 + 4 * 5`**
**具体分析树 (Parse Tree)** 会包含很多没用的中间节点：

```text
      E
    / | \
    E  +  T
    |    / | \
    T   T  *  F
    |   |     |
    F   F     id(5)
    |   |
  id(3) id(4)
```

**抽象语法树 (AST)** 只保留运算核心：

```text
       +
     /   \
    3     *
        /   \
       4     5
```

很明显，AST 更适合后续阶段（如生成汇编代码）进行处理。

## 6. 错误处理

- **恐慌模式 (Panic-mode)**：丢弃输入流中的记号，直到遇到一个同步记号（如分号、右大括号），然后继续分析。
  > 比如：少写了一个分号导致报错，编译器会直接忽略后面几个看不懂的词，直到看到下一个分号才重新开始工作。
- **短语层次恢复 (Phrase-level recovery)**：在特定位置执行局部的修改（如脑补插入缺少的分号），试图修复错误并继续。
