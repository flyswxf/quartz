- 在内存中的一个页维护一个日志, 包含所有[[事务]]进行过的修改
	- 默认log不会被丢失
	- 页满了就写入硬盘
- 使用[[内存管理协议#^f7c2c6|STEAL+NO-FORCE]]

#### Log的表示
- \<Ti  start>
- \<Ti, X,  V1,  V2>
	- Ti：Transaction ID
	- X: Data object ID or Data object address
	- V1: 值原先为V1
	- V2: 值修改为V2
	- **prevLSN**: 在[[ARIES算法]]中使用, 记录Ti的上一个操作的LSN ^798544
- \<Ti  commit>
	- 一旦事务要commit, 先将\<Ti commit>写入日志并将日志**全部刷盘**
- \<Ti  abort> 
	- 事务主动abort, 写入\<Ti  abort> , 接下来写CLR
- \<Ti  End>
	- 事务结束了(commit或abort), 额外写一个\<Ti End>
- **CLR(Compensation Log Records)** ^fea3c9
	- 在[[ARIES算法]]中使用, 用于[[Undo]]过程
	- \<CLR: Undo Ti LSN $LSN$, UndoNext $UndoNext$>
	- undoLSN: 记录CLR undo的修改(属于Ti)的LSN
	- undonextLSN: 记录CLR undo的修改(属于Ti)的之前一个修改(属于Ti), 这是通过prevLSN找到的
	- ![[assets/事务日志流程图.png]]
- \<CHECKPOINT>

#### Log的分类
- 物理日志
	- 记录修改内容的具体地址, 修改前后的值
- 逻辑日志
	- 只记录修改的操作
- 物理逻辑日志
	- 记录修改内容的页, 允许数据库重新分配修改的页内地址
