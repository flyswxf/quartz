## B+ 树的删除操作

从 B+ 树中删除一条数据时，如果删除导致节点内的键值数量低于规定的下限，为了维持 B+ 树的空间利用率约束，需要进行**借用（Redistribution）**或**合并（Merge）**操作。

### 删除步骤

#### 1. 查找并删除
从根节点向下遍历，找到目标键值所在的**叶子节点**，并将其删除。

#### 2. 检查节点约束
- **情况 A：节点键值数符合下限**
  - 删除后，叶子节点的键值数依然 $\ge \lceil \frac{n-1}{2} \rceil$。
  - **操作**：直接完成删除。如果被删除的值正好是父节点中的路由索引值，通常可以选择不更新父节点（只要指针仍然能正确路由即可），或者用新的最小键值替换。
- **情况 B：节点键值数低于下限（下溢 Underflow）**
  - 需要修复该节点。优先考虑向兄弟节点**借用**，借不到再**合并**。

#### 3. 修复下溢（借用与合并规则）

**优先级 1：向兄弟节点借用（Redistribution）**
如果其相邻的兄弟节点（优先看左兄弟，再看右兄弟）的键值数非常充裕（即借出一个键值后，仍满足最低下限约束），则进行借用：
- **向左兄弟借**：将左兄弟的**最大**键值移动到当前节点，并更新父节点中区分这两个节点的路由键。
- **向右兄弟借**：将右兄弟的**最小**键值移动到当前节点，并更新父节点中对应的路由键。

**优先级 2：与兄弟节点合并（Merge）**
如果左右兄弟节点都很“穷”（即它们的键值数都接近下限），借用会导致它们自身下溢，那么只能进行合并：
- 优先尝试与**左兄弟**合并。如果不满足条件（例如没有左兄弟，或者不属于同一个直接父节点），则尝试与**右兄弟**合并。
- **合并操作**：将当前节点的所有剩余键值全部移入兄弟节点中，然后删除当前空节点。

#### 4. 向上更新父节点（递归）
当发生**合并**时，由于少了一个子节点，必须从父节点中删除指向该子节点的指针以及对应的路由键值。
- 这可能导致父节点（中间节点）的指针数也低于下限（$\lceil \frac{n}{2} \rceil$）。
- 如果父节点下溢，则按照同样的逻辑：先尝试向父节点的兄弟节点**借用**（注意这涉及到父节点键值的旋转下移），借不到则与父节点的兄弟节点**合并**（合并时要把根路由键拉下来）。
- 如果合并操作一直向上传递到根节点，导致根节点只剩下唯一的 $1$ 个子节点指针，那么原根节点将被删除，唯一的子节点成为**新的根节点**，此时 **B+ 树的高度减少 1**。

---

### 详细示例：连续删除与合并

**前提**：接着之前连续插入得到的一棵 $n=5$ 的 B+ 树，执行以下系列操作：
`delete 8, delete 10, insert 46, delete 52, delete 32, delete 39, delete 41, delete 45`

**初始状态**：
```text
               [39]
             /      \
      [6, 18]        [52, 80]
     /   |   \       /   |   \
[1,2,5][6,8,10][18,27,32] [39,41,45][52,58,73][80,91,99]
```

#### 1. Delete 8
找到 `[6,8,10]`，删除 8，余下 `[6,10]`。键值数 2 $\ge$ 下限 2，正常。
```text
               [39]
             /      \
      [6, 18]        [52, 80]
     /   |   \       /   |   \
[1,2,5] [6,10] [18,27,32] [39,41,45][52,58,73][80,91,99]
```

#### 2. Delete 10
找到 `[6,10]`，删除 10，余下 `[6]`。发生**下溢**。
向左兄弟 `[1,2,5]` **借用**最大值 5。本节点变为 `[5,6]`，左兄弟变为 `[1,2]`。
更新父节点路由键 `6` 为 `5`：
```text
               [39]
             /      \
      [5, 18]        [52, 80]
     /   |   \       /   |   \
[1,2]  [5,6] [18,27,32] [39,41,45][52,58,73][80,91,99]
```

#### 3. Insert 46
插入到叶子节点 `[39,41,45]`，变为 `[39,41,45,46]`。键值数 4 $\le$ 4，正常。
```text
               [39]
             /      \
      [5, 18]        [52, 80]
     /   |   \       /   |   \
[1,2]  [5,6] [18,27,32] [39,41,45,46][52,58,73][80,91,99]
```

#### 4. Delete 52
找到 `[52,58,73]`，删除 52，余下 `[58,73]`。正常。
*(注：52 是父节点的路由键，可以不更新或更新为新的最小值 58，此处更新为 58 方便理解)*：
```text
               [39]
             /      \
      [5, 18]        [58, 80]
     /   |   \       /   |   \
[1,2]  [5,6] [18,27,32] [39,41,45,46] [58,73] [80,91,99]
```

#### 5. Delete 32
找到 `[18,27,32]`，删除 32，余下 `[18,27]`。正常。
```text
               [39]
             /      \
      [5, 18]        [58, 80]
     /   |   \       /   |   \
[1,2]  [5,6] [18,27]  [39,41,45,46] [58,73] [80,91,99]
```

#### 6. Delete 39, Delete 41
连续删除 `39` 和 `41`，节点 `[39,41,45,46]` 变为 `[45,46]`。正常。
同时更新根节点的路由键为 `45`。
```text
               [45]
             /      \
      [5, 18]        [58, 80]
     /   |   \       /   |   \
[1,2]  [5,6] [18,27]   [45,46]  [58,73] [80,91,99]
```

#### 7. Delete 45
找到 `[45,46]`，删除 45，余下 `[46]`。发生**下溢**。
- 左兄弟是 `[18,27]`，但不属于同一父节点，无法借用或合并。
- 右兄弟是 `[58,73]`（键值数 2），借出会导致其下溢。
- **操作**：将 `[46]` 与右兄弟 `[58,73]` **合并**，变为 `[46,58,73]`。
- **父节点下溢**：父节点 `[58,80]` 失去了一个子节点和路由键 58，只剩下 `[80]`。键值数 1 < 下限 2，父节点发生下溢！
- **中间节点合并**：父节点 `[80]` 的左兄弟 `[5,18]` 键值数 2，无法借用。所以将 `[80]` 与左兄弟 `[5,18]` **合并**，并**拉下**根节点的路由键 45。
- 合并后的新中间节点为 `[5, 18, 45, 80]`，包含 5 个指针。原根节点为空，被删除，树高度减少 1：
```text
                [5, 18, 45, 80]
              /    |    |    |    \
          [1,2]  [5,6] [18,27] [46,58,73] [80,91,99]
```
