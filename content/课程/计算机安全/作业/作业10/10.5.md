# 10.5 扩展Shellcode以包含exit(0)系统调用

## 题目

图 10.8b 中所示的示例 Shellcode 假设 `execve` 系统调用不会返回（只要它成功执行就是这种情况）。然而，为了涵盖它可能失败的可能性，可以扩展该代码，在它之后包含另一个系统调用，这次是调用 `exit(0)`。这将导致程序正常退出，比让它崩溃引来更少的注意。请使用封送参数（marshal arguments）和调用此系统函数所需的额外汇编指令来扩展此 Shellcode。

## 题目分析

本题要求在原有的 `execve` Shellcode 执行失败时，追加 `exit(0)` 系统调用以实现程序的平滑退出，避免产生段错误崩溃（Crash）从而引起系统管理员的警觉。

在 Linux x86 汇编中，执行 `exit(0)` 系统调用需要满足以下条件：
1. **系统调用号**：`exit` 的系统调用号是 1，需要存入 `eax` 寄存器。
2. **参数传递**：`exit(0)` 的参数是 `0`，需要存入 `ebx` 寄存器。
3. **触发调用**：执行 `int $0x80` 触发软件中断（Software Interrupt）。

## 解题过程

在编写 Shellcode 时，一个关键的原则是**不能在机器码中包含空字节（Null Bytes，`\x00`）**，否则会被字符串处理函数（如 `strcpy`）截断。
因此，我们不能直接使用类似 `mov $0, %ebx` 或 `mov $1, %eax` 这样的指令，它们会被编译为包含 `0x00` 的机器码。

我们可以利用异或指令（`xor`）来安全地将寄存器清零，并使用低 8 位寄存器（如 `al`）或自增指令（`inc`）来赋值。需要在原代码的第一个 `int $0x80` 之后追加以下指令：

```assembly
xor %ebx, %ebx    // 将 ebx 寄存器清零，作为 exit 的状态码参数 0
xor %eax, %eax    // 将 eax 寄存器清零
mov $0x01, %al    // 将 exit 的系统调用号 1 放入 al（避免引入空字节）
int $0x80         // 触发软中断，执行 exit(0)
```

将这 4 条指令插入到图 10.8b 原有代码的 `int $0x80` （执行 `execve`）与 `find: call cont` 之间，即可完成扩展。

---
## 参考答案

为了在 `execve` 调用失败时让程序正常退出而不发生崩溃，需要在原汇编代码的 `int $0x80` 指令后追加执行 `exit(0)` 的汇编指令。具体添加的额外指令为：首先使用 `xor %ebx, %ebx` 将退出状态码 0 存入 `ebx` 寄存器；接着使用 `xor %eax, %eax` 配合 `mov $0x01, %al`（或 `inc %eax`）将 `exit` 的系统调用号 1 存入 `eax` 寄存器，这样能有效避免产生空字节（Null Bytes）导致 Shellcode 被截断；最后再次添加 `int $0x80` 触发软中断来执行退出操作。
