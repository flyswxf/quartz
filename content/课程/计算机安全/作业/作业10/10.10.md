# 10.10 重写易受缓冲区溢出攻击的函数

## 题目

重写图 10.10 中显示的函数，使它们不再容易受到缓冲区溢出攻击（Buffer Overflow Attack）。

## 题目分析

图 10.10 给出了两个不安全的 C 语言函数，它们的主要问题在于**缺乏对目标缓冲区大小的边界检查**。

1. **(a) Unsafe byte copy (`copy_buf` 函数)**：
   - **问题**：原函数直接根据输入的 `len` 参数循环复制数据到 `to` 数组中。如果 `pos + len` 的大小超过了 `to` 缓冲区实际分配的容量，就会发生越界写入，导致缓冲区溢出。
   - **修复思路**：需要为函数增加一个参数（例如 `max_len` 或 `to_size`），用于传入目标缓冲区 `to` 的总大小。在复制数据前，必须检查当前的 `pos` 加上要复制的 `len` 是否会超过目标缓冲区的最大容量。

2. **(b) Unsafe byte input (`read_chunk` 函数)**：
   - **问题**：原函数先从文件中读取一个 2 字节的 `len`，然后直接信任这个 `len`，并使用 `fread(to, 1, len, fil)` 读取相应长度的数据到缓冲区 `to`。如果文件被恶意篡改，使读取到的 `len` 非常大，且超过了 `to` 的实际容量，就会引发缓冲区溢出。
   - **修复思路**：与上一个函数类似，需要增加一个参数（例如 `max_len`）来表示目标缓冲区 `to` 的大小限制。在执行第二次 `fread` 读取数据之前，必须校验从文件中读取到的 `len` 是否大于 `max_len`。如果超过了最大容量，则只读取 `max_len` 的数据，或者返回错误。

## 解题过程

根据上述分析，我们可以通过增加边界检查参数来重写这两个函数：

**1. 重写 `copy_buf` 函数**

增加 `max_len` 参数，代表目标缓冲区 `to` 的总容量。在 `for` 循环中，不仅要检查 `i < len`，还要确保写入位置 `pos` 不会达到或超过 `max_len`。

```c
int copy_buf(char *to, int max_len, int pos, char *from, int len)
{
    int i;
    for (i = 0; i < len && pos < max_len; i++) {
        to[pos] = from[i];
        pos++;
    }
    return pos;
}
```

**2. 重写 `read_chunk` 函数**

增加 `max_len` 参数，代表目标缓冲区 `to` 的最大容量。在从文件读取了 `len` 之后，检查 `len` 是否大于 `max_len`。如果大于，则截断为 `max_len`，防止溢出。

```c
short read_chunk(FILE *fil, char *to, short max_len)
{
    short len;
    fread(&len, 2, 1, fil);         /* 读取二进制数据的长度 */
    
    /* 防御缓冲区溢出：如果请求的长度超过了缓冲区的最大容量，则截断它 */
    if (len > max_len) {
        len = max_len;
    }
    
    fread(to, 1, len, fil);         /* 安全地读取指定长度的数据 */
    return len;
}
```
*(注：原题图中 `FILE fil` 存在语法瑕疵，标准 C 库中应为文件指针 `FILE *fil`，在重写时一并修正)*

## 参考答案

为了防御缓冲区溢出攻击，必须在函数中引入目标缓冲区的大小作为参数，并进行严格的边界检查。对于 `copy_buf` 函数，需增加 `max_len` 参数代表目标数组容量，在 `for` 循环条件中加入 `pos < max_len` 的判断，确保复制操作不会越界：`for (i = 0; i < len && pos < max_len; i++)`。对于 `read_chunk` 函数，同样需增加 `max_len` 参数，在从文件读取出需要拷贝的长度 `len` 之后，执行第二次读取前，增加判断 `if (len > max_len) len = max_len;`，从而强制限制读取字节数不超过缓冲区的实际容量。
