### 5.5 题解答

**原 SQL 语句：**
`SELECT id, forename, surname FROM authors WHERE forename = 'david' AND id = 939`

---

**a. What is this statement trying to search from the database? （这条语句试图从数据库中搜索什么？）**

这条语句试图从 `authors`（作者）数据表中查找 `forename`（名字）为 'david' 且 `id` 为 939 的特定记录，并返回该作者的 `id`、`forename`（名字）和 `surname`（姓氏）。

---

**b. Assume that the firstname and id fields are being gathered from user-supplied input... What will be the effect? （假设输入由用户提供，输入 Firstname 为 `david'; drop table employees - -`，id 为 `939`，会有什么影响？）**

如果应用程序没有对用户的输入进行过滤，直接拼接 SQL 语句，最终在数据库中执行的语句将变成：
`SELECT id, forename, surname FROM authors WHERE forename = 'david'; drop table employees - -' AND id = 939`

**产生的影响（经典 SQL 注入攻击）：**
1. 数据库会将其识别为两条独立的指令并依次执行。
2. 首先执行 `SELECT` 查询，查找名字为 'david' 的作者。
3. 接着遇到分号 `;`（语句结束符），数据库会继续执行下一条恶意指令 `drop table employees`，这将会**直接删除数据库中的 `employees`（员工）表**，造成严重的数据丢失。
4. 后面的 `- -`（在 SQL 中表示注释）会将原代码中剩余的 `' AND id = 939` 注释掉，从而避免 SQL 语法错误，确保恶意代码顺利执行。

---

**c. Now suppose the user responds with: firstname: `' OR 9 = 9 - -`, id: `939`. What will be the effect? （如果用户输入 firstname 为 `' OR 9 = 9 - -`，会有什么影响？）**

拼接后的 SQL 语句将变成：
`SELECT id, forename, surname FROM authors WHERE forename = '' OR 9 = 9 - -' AND id = 939`

**产生的影响（逻辑绕过型 SQL 注入）：**
1. 注入代码闭合了前面的单引号，并引入了 `OR 9 = 9` 这个条件。
2. 由于 `9 = 9` 永远为真（True），并且使用了 `OR` 逻辑运算符，导致 `WHERE` 子句的过滤条件形同虚设，对表中的每一行数据都会计算为 True。
3. 结尾的 `- -` 同样注释掉了原语句后面的内容。
4. 最终结果是，该查询会完全绕过原本的身份验证或特定搜索限制，**返回 `authors` 表中所有记录的 `id`、`forename` 和 `surname` 信息**，导致大规模的数据泄露。
