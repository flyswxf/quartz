基于口令（Password）的认证是最广泛使用的身份验证方法，属于[[基本认证方式#1. 你知道什么（Something you know）|“你知道什么（Something you know）”]]类别。

## 基本原理
系统将用户 ID 与其对应的口令进行匹配。为了安全性，系统通常**不直接存储明文口令**，而是存储口令的哈希值（Hash）。用户登录时，系统对输入的口令计算哈希值，并与数据库中存储的值进行比对。

## 口令存储与加盐（Salting）
简单的哈希存储容易受到预计算字典攻击（如[[暴力破解攻击#3. 彩虹表攻击 (Rainbow Table Attack)|彩虹表攻击]]）。为了抵御这种攻击，引入了**加盐（Salting）**机制。
- **盐值（Salt）**：一个随机生成的字符串，在计算哈希前附加到口令上（即 `Hash(Password + Salt)`）。
- **存储**：盐值通常以明文形式与哈希值一起存储在数据库中。
- **作用**：
  1. 阻止使用预计算的彩虹表（Rainbow Tables）。
  2. 即使两个用户的口令相同，由于盐值不同，其存储的哈希值也不同，防止攻击者发现相同密码的用户。

## 常见攻击方式
- **离线字典攻击（Offline Dictionary Attack）**：获取了系统的口令哈希文件后，使用包含大量常见密码的字典进行离线哈希计算比对。
- **特定账户攻击（Specific Account Attack）**：针对某个特定目标（如管理员），在线尝试各种猜测的密码。
- **热门密码攻击（Popular Password Attack）**：使用几个最常见的密码（如 `123456`、`password`）尝试大量不同的用户账户。
- **电子监听（Electronic Monitoring）**：在未加密的网络连接中窃听传输的明文密码。
- **利用用户疏忽**：如用户将密码写在便签上、在多个网站重复使用相同密码。

## 口令选择策略
为了提高安全性，系统通常会采用以下策略来约束用户的口令选择：
1. **用户教育（User Education）**：指导用户不要使用易猜密码，但效果往往有限。
2. **计算机生成口令（Computer-Generated Passwords）**：由系统生成完全随机的强密码，但用户极难记忆。
3. **被动口令检查（Reactive Password Checking）**：定期运行破解工具扫描系统现有的密码，强制破解出的弱密码用户进行更改（占用计算资源）。
4. **主动口令检查（Proactive Password Checking）**：在用户设定新密码时，实时检查其复杂度（长度、字符类型）或是否在弱密码黑名单中。这是目前最推荐且最普遍的策略。
