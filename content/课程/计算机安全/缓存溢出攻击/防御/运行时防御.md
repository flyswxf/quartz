# 运行时防御 (Run-Time Defenses)

运行时防御旨在通过操作系统或硬件级别的安全机制，在程序执行过程中阻断缓冲区溢出攻击的实施（例如阻止恶意代码的执行或阻止攻击者定位目标地址）。主要包含以下三种核心方法：

## 1. 可执行地址空间保护 (Executable Address Space Protection)
- **概念**：通过限制内存区域的执行权限，防止攻击者注入的 Shellcode 被 CPU 执行。
- **机制 (W^X / DEP / NX Bit)**：
  - 核心原则是“写与执行互斥”（Write XOR Execute，即 $W \oplus X$）。一块内存区域要么可以被写入，要么可以被执行，但不能同时具备这两种权限。
  - **NX Bit (No-eXecute bit)**：现代 CPU 硬件支持的页表属性。操作系统利用此硬件特性，将栈区（Stack）、堆区（Heap）和全局数据区标记为不可执行（Non-executable）。
- **防御效果**：即使攻击者通过缓冲区溢出成功将恶意代码（Shellcode）注入到栈或堆中，并篡改了控制流，当 CPU 尝试从这些不可执行的内存区域取指时，会触发硬件异常（如段错误），从而挫败传统的代码注入攻击。
- **局限性**：无法防御“代码复用攻击”（Code-Reuse Attacks），例如面向返回的编程（Return-Oriented Programming, ROP）或 Return-to-libc 攻击，因为这些攻击利用的是内存中已经存在的、具有可执行权限的合法代码。

## 2. 地址空间随机化 (Address Space Randomization)
- **概念**：通过在程序每次启动时随机化内存布局，使攻击者无法预测目标指令或数据的确切内存地址。
- **机制 (ASLR - Address Space Layout Randomization)**：
  - 操作系统在加载程序时，会随机化关键内存区域的基地址，包括：
    - 栈区 (Stack)
    - 堆区 (Heap)
    - 动态链接库 / 共享库 (Shared Libraries, 如 libc)
    - 甚至程序自身的可执行代码和数据段（需要结合 PIE - Position Independent Executables 技术）。
- **防御效果**：缓冲区溢出攻击（尤其是 ROP 和 Return-to-libc）通常需要硬编码特定的内存地址（如 `system()` 函数的地址或注入的 Shellcode 的地址）。ASLR 使得这些地址在每次运行时都发生变化，攻击者只能依靠盲目猜测，极大地提高了攻击失败（导致程序崩溃）的概率。
- **局限性**：在 32 位系统上，由于地址空间较小，随机化的熵值（Entropy）不足，攻击者可能通过暴力破解（Brute-force）绕过。此外，内存泄漏（Memory Leak）漏洞可能暴露随机化后的基地址，导致 ASLR 失效。

## 3. 保护页 (Guard Pages)
- **概念**：在内存中关键区域之间插入不可访问的虚拟内存页，用于隔离并检测连续的内存越界访问。
- **机制**：
  - 操作系统在分配内存时，在栈与栈之间、或堆块与堆块之间，映射一个或多个不分配物理内存、且被标记为不可读写的虚拟内存页（Guard Page）。
  - 当程序发生缓冲区溢出，且溢出的数据试图连续跨越当前内存区域边界写入到 Guard Page 时，会立即触发缺页异常（Page Fault）或段错误（Segmentation Fault）。
- **防御效果**：非常有效地防止顺序越界写入（Sequential Out-of-bounds Writes），例如 `strcpy` 导致的无界拷贝。一旦触碰 Guard Page，操作系统会立刻感知异常并终止程序。
- **局限性**：无法防御能够进行“跳跃式”内存写入的攻击（例如利用任意地址写入漏洞），攻击者可以通过控制偏移量直接跳过 Guard Page 写入目标地址。
