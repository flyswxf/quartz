Shellcode 是一段专门精心编写的机器指令（Machine Code），通常作为攻击载荷（Payload）被注入到目标程序的内存中，用于利用软件漏洞（如缓冲区溢出）。

**命名来源**：其最经典的攻击目标是在受害机器上生成并弹出一个命令行 Shell（如 Linux 下的 `/bin/sh` 或 Windows 下的 `cmd.exe`），从而允许攻击者执行任意系统命令。

## 2. Shellcode 的核心约束条件 (Core Constraints)
在真实攻击场景中，由于漏洞利用环境的特殊性，编写 Shellcode 必须满足以下严苛的约束条件：

### 2.1 位置无关性 (Position-Independent)
- **原因**：Shellcode 被注入到目标进程（如栈或堆）时的确切内存地址往往是未知的或动态变化的（尤其是存在 [[运行时防御#2. 地址空间随机化 (Address Space Randomization)|ASLR 机制]]时）。
- **要求**：代码不能包含任何硬编码的绝对内存地址。必须使用相对寻址（如基于程序计数器的相对跳转），或者通过寄存器在运行时动态计算数据的地址。

### 2.2 绝对避免空字符 (No Null Bytes)
- **原因**：绝大多数缓冲区溢出漏洞源于 C 语言中不安全的字符串处理函数（如 `strcpy`、`sprintf`、`gets`）。这些函数在复制数据时，一旦遇到字符串结束符即空字符（`\x00`）就会立即停止操作。

- **常用的 Shellcode 指令技巧**：
  - 寄存器清零: `xor %ebx, %ebx`
  - 赋予小数值：
    - 先清零32 位寄存器 `%eax`，再对低8位寄存器（如 `%al`）赋值：
    - `xor %eax, %eax` 
    - `mov $0xb, %al`
    - **错误示范**：如果直接写 `mov $0xb, %eax`，因为目标是 32 位寄存器，编译器会将立即数补齐为 32 位（即 `0x0000000b`），导致生成的机器码中出现 3 个致命的空字符 `\x00`。

## 3. 系统调用的执行机制 (Execution Mechanism)
Shellcode 极少调用高级语言的库函数（如 C 标准库中的 `system()`），因为这些库在目标内存中的加载地址是不确定的。相反，Shellcode 通常直接通过底层的**系统调用 (System Calls)** 与操作系统内核交互。

以 x86 架构下的 Linux 为例，调用 `execve("/bin/sh", ["/bin/sh", NULL], NULL)` 的过程如下：

**背景知识：系统调用传参规范 (Syscall Calling Convention)**
在 x86 Linux 中，通过 `int $0x80` 触发系统调用时，内核期望按照特定的寄存器顺序来接收系统调用号和参数，这与 C 语言函数的栈传参机制不同：
- `$EAX`：存放系统调用号 (System Call Number)。
- `$EBX`, `$ECX`, `$EDX`, `$ESI`, `$EDI`, `$EBP`：依次存放第 1 到第 6 个参数。

针对这一系统调用，参数的映射关系为：
```c
int execve(const char *filename, char *const argv[], char *const envp[]);
``` 

1. **设置系统调用号 ($EAX$)**：
   将 `execve` 的调用号 11 (即 `$0x0b$`) 放入 `EAX` 寄存器。
2. **传递第 1 个参数 ($EBX$ -> filename)**：
   `$EBX` 寄存器必须指向要执行的程序路径字符串，即指向内存中的 `"/bin/sh\0"`。
3. **传递第 2 个参数 ($ECX$ -> argv)**：
   `$ECX` 寄存器必须指向参数数组 (`argv`)。数组的第一个元素通常是程序自身的名称（指向 `"/bin/sh\0"`），最后一个元素必须是 `NULL` 截断符。
4. **传递第 3 个参数 ($EDX$ -> envp)**：
   `$EDX` 寄存器指向环境变量数组 (`envp`)。在简单的 Shellcode 中，通常不需要环境变量，因此让 `$EDX` 指向 `NULL`（即 0）即可。
5. **触发中断**：
   执行 `int $0x80` 指令，触发软件中断。CPU 陷入内核态，由操作系统读取上述寄存器并执行对应的系统调用。

## 4. NOP 雪橇 (NOP Sled)
- **概念**：为了显著提高缓冲区溢出攻击的成功率，攻击者通常会在真正的 Shellcode 前面填充大量连续的“空操作”指令（NOP，No-Operation，在 x86 架构中机器码为 `\x90`）。这片区域被称为 NOP 雪橇。
- **作用**：在猜测被劫持的返回地址时，精确命中 Shellcode 的第一条指令难度极高。有了 NOP 雪橇后，只要篡改后的返回地址落入雪橇的任意位置，CPU 就会顺着这些什么都不做的指令一直“滑行”下去，最终无缝衔接并执行真正的 Shellcode。
