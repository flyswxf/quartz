# HIDS 类型

> [!info] 三种检测引擎
> HIDS 和 NIDS 一样，也有三种检测引擎：异常检测、签名检测、启发式检测。区别在于 HIDS 的数据源是**主机内部活动**而非网络流量。

## 异常 HIDS

> [!example] 基于系统调用的异常检测
> 每个程序运行时都会调用一系列系统调用（如 `open → read → close`）。异常 HIDS 学习程序的"正常调用序列"，发现异常序列就报警。
>
> ```
> 正常: open → read → close → write
> 异常: open → exec → shell → write  ← 从"读文件"跳到"执行命令"，可疑！
> ```

> [!example] 基于用户行为的异常检测
>
> | 行为特征 | 正常 | 异常 |
> | -------- | ---- | ---- |
> | 登录时间 | 9:00-18:00 | 凌晨 3:00 |
> | 命令使用 | ls, vim, git | nc, wget, chmod 777 |
> | 文件访问 | 项目代码 | /etc/shadow |
> | 资源使用 | CPU 30% | CPU 95% |

## 签名/启发式 HIDS

> [!example] 签名 HIDS
> 匹配已知攻击的特征码：
>
> | 签名类型 | 例子 |
> | -------- | ---- |
> | **文件签名** | 已知恶意软件的哈希值（MD5/SHA256） |
> | **日志签名** | "Failed password for root" 大量出现 |
> | **配置签名** | SSH 允许 root 直接登录 |

> [!example] 启发式 HIDS
> 基于规则判断可疑行为：
>
> ```
> IF 用户身份 = 普通用户
> AND 执行命令 in [sudo, su, chmod 777]
> AND 未通过正式授权流程
> → 疑似权限提升
> ```

## 分布式 HIDS

当企业有上百台服务器时，每台都装 HIDS 传感器，需要一个**中央管理平台**来统一管控。

```
主机A (传感器) ──┐
主机B (传感器) ──┼──→ 中央管理服务器 ──→ 管理控制台
主机C (传感器) ──┘
```

| 组件           | 作用                       |
| -------------- | -------------------------- |
| **本地传感器** | 部署在每台主机上，采集数据 |
| **本地分析器** | 初步分析和过滤，减少数据量 |
| **中央服务器** | 汇聚所有主机数据，关联分析 |
| **管理控制台** | 配置策略、查看报告         |

> [!tip] 分布式 HIDS 的价值
> 单台主机看不出攻击模式，但把 100 台主机的日志关联起来，就能发现：攻击者从主机 A 的 Web 漏洞进入，横向移动到主机 B，再提权到主机 C。这种**跨主机的攻击链**只有分布式 HIDS 才能发现。
