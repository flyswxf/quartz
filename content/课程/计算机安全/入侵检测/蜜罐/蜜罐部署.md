# 蜜罐部署

> [!info] 部署位置决定效果
> 蜜罐放在哪里、看起来像什么，直接决定了它能不能吸引到攻击者。放在错误的位置，攻击者根本不会发现它。

## 部署位置

| 位置         | 用途                      | 吸引谁                       |
| ------------ | ------------------------- | ---------------------------- |
| **DMZ**      | 模拟公开服务器            | 外部攻击者                   |
| **内部网络** | 模拟内部数据库/文件服务器 | 内部威胁、已突破边界的攻击者 |
| **云环境**   | 模拟云主机                | 云环境攻击者                 |
| **IoT 网络** | 模拟物联网设备            | IoT 恶意软件（如 Mirai）     |

## 蜜网架构

```
[互联网]
    ↓
[入口路由器] ← 流量捕获
    ↓
[蜜网网关] ← 控制和监控（关键！）
    ↓
[蜜罐1: Web服务器]    ← 看起来像公司官网
[蜜罐2: 数据库服务器]  ← 看起来像生产数据库
[蜜罐3: 邮件服务器]    ← 看起来像邮件系统
    ↓
[数据收集服务器] ← 所有活动日志汇总
```

> [!warning] 蜜网网关是核心
> 蜜网网关负责：
> - **数据控制**：限制蜜罐对外连接，防止被当作跳板
> - **数据捕获**：记录所有进出蜜罐的流量
> - **活动监控**：在蜜罐被攻陷时发出警报

## 部署注意事项

| 考虑因素     | 要求                                           |
| ------------ | ---------------------------------------------- |
| **隔离性**   | 蜜罐与真实生产系统完全隔离                     |
| **真实性**   | 蜜罐要像真的——开放常见服务、有看起来合理的文件 |
| **监控性**   | 蜜罐内的一举一动都必须被记录                   |
| **法律合规** | 某些地区"诱捕"可能有法律风险                   |

## 蜜罐的实战价值

> [!example] 案例：零日攻击发现
> 1. 蜜罐捕获到未知恶意软件
> 2. 安全团队分析攻击行为和载荷
> 3. 提取攻击特征（IOC）
> 4. 识别零日漏洞
> 5. 通知厂商修补
> 6. 将特征推送到全网 IDS 签名库

> [!example] 案例：增强 IDS 检测能力
> 蜜罐检测到新攻击 → 提取签名 → 更新 IDS 签名库 → 全网部署新规则 → 检测同类攻击
>
> 这就是蜜罐与 [[入侵检测原理与需求|IDS]] 的协同效应：蜜罐负责"养蛊"（引诱攻击者），IDS 负责"撒网"（全网检测）。
