# 入侵检测交换格式

> [!info] 为什么需要标准化？
> 企业里可能有不同厂商的 IDS、防火墙、SIEM 系统。如果每家都用自己的数据格式，它们之间就无法对话。标准化交换格式就是让所有安全设备说"同一种语言"。

## IDMEF (Intrusion Detection Message Exchange Format)

最主流的入侵检测消息标准，由 IETF 定义。

### 消息结构

```xml
<Alert>
  <Analyzer>sensor-01 (192.168.1.10)</Analyzer>
  <CreateTime>2024-03-15T14:23:01+08:00</CreateTime>
  <Source>
    <Address>203.0.113.42</Address>
    <Port>43210</Port>
  </Source>
  <Target>
    <Address>192.168.1.100</Address>
    <Port>80</Port>
    <Service>HTTP</Service>
  </Target>
  <Classification>SQL Injection</Classification>
  <Assessment>
    <Impact severity="high">Database compromise</Impact>
    <Action>blocked</Action>
  </Assessment>
</Alert>
```

### 核心字段

| 字段               | 含义                         |
| ------------------ | ---------------------------- |
| **Analyzer**       | 哪个传感器产生的警报         |
| **CreateTime**     | 什么时候检测到的             |
| **Source**         | 攻击来自哪里（IP/端口/用户） |
| **Target**         | 攻击针对谁（IP/端口/服务）   |
| **Classification** | 什么类型的攻击               |
| **Assessment**     | 严重程度和影响评估           |

## CIDF (Common Intrusion Detection Framework)

另一个标准化框架，定义了 IDS 的**四大组件**：

| 组件                   | 角色           |
| ---------------------- | -------------- |
| **传感器** (Sensor)    | 采集原始数据   |
| **分析器** (Analyzer)  | 检测入侵       |
| **数据库** (Database)  | 存储事件和告警 |
| **响应器** (Responder) | 执行响应动作   |

> [!tip] IDMEF 定义"说什么"，CIDF 定义"谁来说"
> IDMEF 关注的是消息格式（数据怎么写），CIDF 关注的是系统架构（组件怎么配合）。两者互补。
