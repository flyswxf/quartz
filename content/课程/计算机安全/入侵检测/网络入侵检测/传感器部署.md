# NIDS 传感器部署

> [!info] 部署位置决定检测能力
> 传感器放在哪里，决定了它能看到什么流量。放错了位置，有些攻击就看不到。

## 部署位置

```
互联网
  ↓
[防火墙] ←── 传感器 A（监控外部攻击尝试）
  ↓
[DMZ]    ←── 传感器 B（监控公开服务攻击）
  ↓
[内部网络] ←── 传感器 C（监控内部威胁和横向移动）
  ↓
[核心网络] ←── 传感器 D（保护高价值资产）
```

| 位置           | 监控目标       | 检测内容                 |
| -------------- | -------------- | ------------------------ |
| **防火墙外侧** | 互联网入口     | 外部攻击尝试、扫描、探测 |
| **DMZ 区域**   | Web/邮件服务器 | 针对公开服务的攻击       |
| **内部网络**   | 员工和内部系统 | 内部威胁、横向移动       |
| **核心网络**   | 数据库、域控   | 针对高价值目标的攻击     |

> [!tip] 最少部署两个
> 至少在防火墙两侧各放一个：一个看外部攻击，一个看内部活动。预算充足再在 DMZ 和核心网络加传感器。

## 警报日志

### 日志长什么样

| 字段         | 示例                      |
| ------------ | ------------------------- |
| **时间戳**   | 2024-03-15 14:23:01       |
| **源 IP**    | 203.0.113.42              |
| **目标 IP**  | 192.168.1.100             |
| **端口**     | 80 (HTTP)                 |
| **签名 ID**  | SID-2024-0891             |
| **严重级别** | 高                        |
| **负载摘要** | SQL 注入尝试：' OR 1=1 -- |

### 日志管理流程

```mermaid
graph LR
    A[传感器] --> B[日志收集器]
    B --> C[数据库]
    C --> D[分析平台]
    D --> E[安全报告]
```

> [!warning] 日志量是大问题
> 一个中等规模网络每天可能产生**数百万条**日志。没有集中化的日志管理，安全人员根本看不过来。
