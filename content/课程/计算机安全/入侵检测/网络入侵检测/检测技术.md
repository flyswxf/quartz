# NIDS 检测技术

> [!info] NIDS 怎么判断"这是攻击"？
> 三种技术路线：签名匹配、异常检测、状态协议分析。实际部署中通常组合使用。

## 1. 签名检测

匹配已知攻击特征，类似杀毒软件：

| 签名类型       | 例子                                     |
| -------------- | ---------------------------------------- |
| **字符串匹配** | HTTP 请求中包含 `<script>` → XSS 攻击    |
| **协议违规**   | DNS 响应大小超过 512 字节 → DNS 放大攻击 |
| **端口扫描**   | 1 分钟内同一 IP 探测 50+ 端口            |

> ✅ 快速、准确、低误报
> ❌ 只能抓已知攻击，签名库要持续更新

## 2. 异常检测

建立正常流量基线，检测偏离：

| 指标     | 正常              | 触发异常         |
| -------- | ----------------- | ---------------- |
| 流量速率 | 稳定 100Mbps      | 突然飙升到 1Gbps |
| 连接数   | ~500              | 突然 >5000       |
| 协议分布 | HTTP 70%, DNS 20% | ICMP 突然占 80%  |

> ✅ 能发现未知攻击和 DDoS
> ❌ 误报率高，正常流量变化也会触发

## 3. 状态协议分析

跟踪协议的**状态机**，检测协议违规：

```
正常 TCP 握手: SYN → SYN-ACK → ACK
异常: 收到 SYN-ACK 但从未发送 SYN → 可能是伪造包
```

> ✅ 能发现协议滥用和畸形包
> ❌ 实现复杂，需要维护每个协议的状态机

## NIDS 的局限

| 局限         | 说明                               |
| ------------ | ---------------------------------- |
| **加密流量** | HTTPS/TLS 流量对 NIDS 来说是乱码   |
| **高速网络** | 10Gbps+ 环境下可能丢包             |
| **内部威胁** | 不经过 NIDS 传感器的内部流量看不到 |
| **误报**     | 正常流量变化可能触发警报           |

> [!tip] NIDS 的局限恰好是 [[HIDS优势|HIDS]] 的强项
> 加密流量、内部威胁、系统级活动——这些 NIDS 看不到的，HIDS 都能检测。所以两者要配合使用。
