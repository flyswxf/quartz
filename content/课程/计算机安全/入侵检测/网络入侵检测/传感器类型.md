# NIDS 传感器类型

> [!info] 传感器 = NIDS 的"眼睛"
> NIDS 传感器部署在网络中，负责"看"流量。有两种"看"的方式：站在路中间看（内联），或者站在路边看（被动）。

## 内联 vs 被动

| 特性           | 内联传感器 (Inline)   | 被动传感器 (Passive)     |
| -------------- | --------------------- | ------------------------ |
| **部署位置**   | 串接在网络链路中      | 旁路监听（镜像端口/TAP） |
| **流量路径**   | 必须经过传感器        | 传感器只看流量副本       |
| **入侵防御**   | ✅ 可阻断攻击          | ❌ 只能报警               |
| **单点故障**   | ❌ 传感器挂了=网络断了 | ✅ 传感器挂了不影响网络   |
| **性能影响**   | ❌ 可能引入延迟        | ✅ 不影响网络性能         |
| **部署复杂度** | 高（要改网络拓扑）    | 低（配镜像端口就行）     |

> [!question] 为什么被动传感器更常用？
> 核心原因：**可靠性 > 防御能力**。
>
> 网络中断的代价远大于"少阻断几个攻击"。内联传感器一旦故障或过载，整段网络瘫痪。被动传感器即使宕机，网络照常运行。需要阻断能力时，通常由防火墙来承担，而不是让 NIDS 冒单点故障的风险。

## 按检测方式分类

| 类型         | 原理               | 特点                         |
| ------------ | ------------------ | ---------------------------- |
| **签名匹配** | 匹配已知攻击特征   | 快速、准确、但只能抓已知攻击 |
| **协议分析** | 深度解析协议合规性 | 能发现协议滥用和畸形包       |
| **流量分析** | 分析流量模式异常   | 能发现 DDoS、扫描等行为      |

> [!tip] 签名匹配 + 流量分析 = 最常见组合
> 大多数 NIDS 同时使用签名匹配（抓已知攻击）和流量分析（发现异常模式），两者互补。
