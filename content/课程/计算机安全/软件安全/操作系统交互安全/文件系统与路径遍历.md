## 什么是路径遍历漏洞？

路径遍历 (Path Traversal) 漏洞，又称目录遍历 (Directory Traversal)，发生在应用程序接收用户输入来构建文件路径，并且未能正确验证或清理该输入时。

攻击者可以通过输入特定的文件系统导航字符（如 `../` 或 `..\`），跳出应用程序原本预期的目录结构，从而访问、读取或覆盖文件系统上的任意文件。

## 漏洞危害

- **信息泄露：** 攻击者可以读取包含敏感信息的文件，如 Linux 系统的 `/etc/passwd`，Windows 的 `C:\Windows\win.ini`，或应用程序的配置文件、源代码、数据库密码等。
- **文件覆盖与代码执行：** 如果应用程序允许文件写入操作，攻击者可能通过路径遍历覆盖关键系统文件或上传恶意脚本到 Web 目录中执行。

## 漏洞示例

假设一个 Web 应用通过以下方式提供图片下载：
```
http://example.com/download?file=image.jpg
```
后台代码可能是：
```python
# 不安全的实现
file_name = request.GET['file']
file_path = "/var/www/images/" + file_name
open(file_path, 'r')
```
如果攻击者将 URL 修改为：
```
http://example.com/download?file=../../../../etc/passwd
```
最终读取的文件路径就变成了 `/var/www/images/../../../../etc/passwd`，操作系统会将其解析为 `/etc/passwd`，从而泄露密码文件。

## 绕过技巧

攻击者常使用各种技巧绕过简单的黑名单过滤：
- URL 编码：将 `../` 编码为 `%2e%2e%2f`。
- 双重 URL 编码：过滤逻辑解码一次，底层系统解码第二次。
- 操作系统特性：在 Windows 系统中，同时支持 `/` 和 `\` 作为路径分隔符。
- 空字节注入：在某些 C 语言编写的底层库中，输入 `../../../etc/passwd%00.jpg` 会在 `%00` 处截断，绕过后缀名检查。

## 防护方法

1. **避免直接使用用户输入访问文件：**
   - 如果可能，不要将用户输入直接映射到文件系统。
   - 使用间接引用：例如，使用数据库中的 ID 映射到文件，用户只传递 ID。

2. **严格的白名单验证：**
   - 验证输入是否只包含允许的字符（如仅字母和数字）。

3. **规范化路径检查 (Path Normalization)：**
   - 这是防御路径遍历的关键技术。在打开文件之前，将包含 `../` 和 `./` 等相对路径符号的路径解析为绝对路径，然后检查该绝对路径是否仍然位于预期的基础目录中。
   - 示例（Java）：
     ```java
     File file = new File(BASE_DIR, userInput);
     String canonicalPath = file.getCanonicalPath();
     if (!canonicalPath.startsWith(BASE_DIR_CANONICAL)) {
         throw new SecurityException("非法的文件访问");
     }
     ```

4. **沙箱与权限控制：**
   - 使用操作系统的权限控制机制，确保运行应用程序的账户只有读取/写入必要目录的最低权限。
   - 在 Linux 中，可以使用 `chroot` 限制进程只能访问特定的目录树。
