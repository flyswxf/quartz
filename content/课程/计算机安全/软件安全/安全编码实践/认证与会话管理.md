
认证和会话管理是应用安全的门户。设计不当会导致攻击者轻易接管其他用户的账户。

## 1. 认证 (Authentication)

认证是确认用户身份的过程。

### [[基本认证方式#多因素认证（Multifactor Authentication, MFA）|多因素认证 (MFA)]]
仅依靠密码（单因素认证）在现代安全威胁下已显得非常脆弱。
- **最佳实践：** 为关键操作和高权限账户强制启用多因素认证。结合“你知道的”（密码）、“你拥有的”（手机验证码、硬件 Token）或“你本身的”（生物特征）。

### 密码策略
- 限制密码最小长度（例如至少 8 或 12 个字符）。
- 不应过度强制复杂的字符组合要求（如必须包含大小写、特殊字符等），因为这往往导致用户采用可预测的模式（如 `Password123!`）或将密码写在纸上。NIST 目前的建议是：允许长密码（Passphrase），并检查密码是否出现在已泄露的密码黑名单中。
- 实施账户锁定或速率限制策略，防止[[暴力破解攻击]]和撞库攻击。

## 2. 会话管理 (Session Management)

由于 HTTP 是无状态协议，应用程序需要通过会话令牌 (Session Token) 来维持用户的登录状态。

### 会话令牌的生成
- 令牌必须足够长且具有极高的熵（随机性），使其无法被猜测或暴力破解。
- 必须使用密码学安全的随机数生成器 (CSPRNG) 生成令牌。

### 保护 Session Cookie
如果使用 Cookie 传递会话令牌，必须设置正确的安全属性：
- **`Secure` 标志：** 指示浏览器仅通过加密的 HTTPS 连接传输该 Cookie，防止网络嗅探。
- **`HttpOnly` 标志：** 禁止客户端 JavaScript（如 `document.cookie`）访问该 Cookie，有效防止 XSS 攻击窃取会话。
- **`SameSite` 标志：** 设置为 `Strict` 或 `Lax`，控制跨域请求时是否发送 Cookie，这是防御跨站请求伪造 (CSRF) 攻击的关键机制。

### 会话生命周期
- **绝对超时与空闲超时：** 会话不能永久有效。应设置空闲超时（例如 30 分钟无操作则注销）和绝对超时（例如 24 小时后强制重新登录）。
- **登出与销毁：** 提供明确的“注销”按钮。用户注销时，服务端必须彻底销毁该会话，而不能仅仅在客户端删除 Cookie。
- **重新认证与会话重置：** 在发生权限变更（如普通用户升级为管理员）或进行敏感操作（如修改密码、大额转账）时，应要求用户重新输入密码，并在认证成功后**重新生成新的会话令牌**。这可以有效防止会话固定 (Session Fixation) 攻击。

## 3. 现代架构下的无状态认证 (JWT)

在微服务和前后端分离架构中，JSON Web Token (JWT) 被广泛使用。
- **防篡改：** JWT 的安全性依赖于签名（Signature）。服务端必须严格校验 JWT 的签名，确保其未被篡改。
- **敏感数据：** JWT 的载荷（Payload）通常只是 Base64 编码的明文，**绝不能**在其中放置密码等敏感信息。
- **撤销难题：** 与传统服务端存储的 Session 不同，JWT 签发后在过期前默认始终有效。如果需要提前撤销（如用户修改密码或设备丢失），需要引入黑名单机制或刷新令牌 (Refresh Token) 机制，这增加了系统复杂性。
