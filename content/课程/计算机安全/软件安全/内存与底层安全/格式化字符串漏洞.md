# 格式化字符串漏洞 (Format String Vulnerability)

## 基本概念

格式化字符串漏洞发生在程序将用户输入直接作为格式化函数的控制字符串（Format String）时。攻击者可以构造包含特定格式化占位符（如 `%x`, `%s`, `%n`）的恶意字符串，从而读取或写入进程的任意内存。

常见的格式化函数包括：`printf`, `sprintf`, `fprintf`, `syslog` 等。

## 漏洞原理

在 C 语言中，格式化函数根据格式化字符串中的占位符，从栈中提取相应的参数并进行格式化输出。如果格式化字符串受攻击者控制，且攻击者提供的占位符数量多于实际传递的参数，函数会继续从栈中读取后续的数据，将其视为参数处理。

### 内存读取 (Information Leak)
- 使用 `%x` 或 `%p` 可以读取栈上的数据，泄露敏感信息（如指针、Canary 值、密码等）。
- 使用 `%s` 可以将栈上的数据视为指针，并读取该指针指向的字符串内容。

### 内存写入 (Arbitrary Write)
- 格式化字符串中有一个特殊的占位符 `%n`。它的作用不是输出，而是将**目前为止已输出的字符总数**写入到一个指针所指向的内存地址中。
- 攻击者通过精心构造输出字符的数量和内存地址，可以利用 `%n` 修改任意内存位置的值（如修改函数的返回地址或 GOT 表条目）。

## 示例分析

不安全的代码示例：
```c
void log_message(char *user_input) {
    // 错误：直接将用户输入作为格式化字符串
    printf(user_input); 
}
```
如果用户输入 `%x %x %x %x`，程序将打印出栈上的前 4 个值。
如果用户输入特定的地址和 `%n`，则可能造成严重的内存篡改。

安全的写法应为：
```c
void log_message(char *user_input) {
    // 正确：使用固定的格式化字符串，将输入作为参数传递
    printf("%s", user_input); 
}
```

## 防护与缓解

1. **安全编码：** 永远不要将不可信的输入直接用作格式化字符串。如果需要输出字符串，务必使用 `%s` 占位符。
2. **编译器警告：** 现代编译器（如 GCC/Clang）在开启警告选项（如 `-Wformat`，`-Wformat-security`）时，能够检测出非静态的格式化字符串，并发出警告或将其视为错误。
3. **运行时保护：** 某些操作系统和 C 库增强了对 `%n` 的限制，例如禁止向只读内存或某些关键区域写入。

## 总结
格式化字符串漏洞是一种威力巨大但相对容易防御的漏洞。严格遵守**格式化字符串必须是常量**的原则，即可完全杜绝此类漏洞。
