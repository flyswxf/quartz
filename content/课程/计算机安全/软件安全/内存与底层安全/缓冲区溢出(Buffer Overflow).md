## 基本概念

缓冲区溢出是一种经典的内存破坏漏洞。当程序试图向固定长度的内存块（缓冲区）中写入超出其容量的数据时，就会发生溢出。多余的数据会覆盖相邻的内存区域，从而导致程序崩溃、数据损坏，甚至被恶意利用以执行任意代码。

缓冲区溢出通常发生在需要手动管理内存的语言中，如 C 和 C++。

## 漏洞原理

在 C 语言中，数组和指针操作缺乏自动的边界检查。如果使用了不安全的字符串处理函数（如 `strcpy`、`gets`），或者在循环复制数据时没有正确计算长度，就极易引发溢出。

### 栈溢出 (Stack Overflow)
最常见的缓冲区溢出类型。[[函数调用机制|函数调用]]时，局部变量、返回地址和寄存器状态被保存在栈帧中。
- 攻击者通过向局部数组写入超长数据，覆盖保存在栈上的**函数返回地址 (Return Address)**。
- 当函数执行 `ret` 指令返回时，会跳转到被攻击者篡改的地址，从而执行攻击者注入的恶意代码（Shellcode）或跳转到其他代码片段（如 ROP 攻击）。

### 堆溢出 (Heap Overflow)
发生在动态分配的内存区域（使用 `malloc` 或 `new` 分配）。
- 覆盖堆块的元数据（如管理堆块的链表指针）。
- 当程序再次分配或释放内存时，堆管理器处理被篡改的元数据，可能导致任意地址写入，进而控制程序执行流。

## 示例分析

不安全的代码示例：
```c
void vulnerable_function(char *input) {
    char buffer[64];
    // strcpy 不检查目标缓冲区大小，直接复制直到遇到 '\0'
    strcpy(buffer, input); 
}
```
如果 `input` 的长度超过 64 字节，`buffer` 就会溢出，覆盖栈上的返回地址。

## 防护机制

现代操作系统和编译器引入了多种机制来防御缓冲区溢出攻击：

1. **栈保护 / 金丝雀 (Stack Canary / Stack Cookie)**
   - 编译器在栈上的局部变量和返回地址之间插入一个随机值（Canary）。
   - 在函数返回前检查该值是否被修改。如果溢出发生，Canary 通常会被覆盖，程序将检测到异常并终止。
2. **数据执行保护 (DEP / NX bit)**
   - 将栈和堆等数据段标记为不可执行。
   - 即使攻击者成功将 Shellcode 注入到栈或堆中，CPU 也会拒绝执行这些内存区域的代码。
3. **地址空间布局随机化 (ASLR)**
   - 每次程序运行时，随机化堆、栈、共享库和可执行文件的内存地址。
   - 这使得攻击者很难预测返回地址或系统函数的地址（如 `system`）。

## 安全编码建议

- **使用安全的字符串函数：** 避免使用 `gets`、`strcpy`、`strcat`、`sprintf`。改用 `fgets`、`strncpy`、`strncat`、`snprintf`，或使用更安全的替代库（如 C11 的 `_s` 系列函数）。
- **严格边界检查：** 在进行内存拷贝或数组访问前，务必验证输入长度。
- **使用现代编程语言：** 尽可能使用 Rust、Go、Java 等内存安全的语言，这些语言内置了边界检查和自动内存管理机制。
