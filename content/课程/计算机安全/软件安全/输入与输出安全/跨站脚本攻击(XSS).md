## 什么是 XSS？

跨站脚本攻击 (Cross-Site Scripting, XSS) 是一种常见的 Web 安全漏洞。攻击者通过在目标网站上注入恶意的客户端脚本（通常是 JavaScript），当其他用户访问该网页时，这些脚本在用户的浏览器中执行。

XSS 的危害包括：窃取用户的 Cookie（特别是 Session ID）、劫持用户会话、进行网络钓鱼、篡改页面内容、强制用户执行意外操作（如点赞、转账，结合 CSRF）。

## XSS 的分类

根据恶意脚本注入和触发的方式，XSS 主要分为三种类型：

### 1. 反射型 XSS (Reflected XSS)
- **原理：** 恶意脚本包含在 URL 或 HTTP 请求参数中。服务器接收到请求后，未经过滤直接将恶意脚本“反射”到 HTTP 响应的 HTML 中。
- **特点：** 非持久化。攻击者通常需要诱导受害者点击包含恶意载荷的特制链接。
- **场景：** 搜索结果页面、错误提示页面等直接显示用户输入的地方。

### 2. 存储型 XSS (Stored XSS)
- **原理：** 攻击者将恶意脚本提交并**永久存储**在目标服务器的数据库中。当其他用户请求包含该数据的页面时，恶意脚本被服务器提取并包含在响应中。
- **特点：** 持久化，危害极大。不需要诱导用户点击特定链接，用户只要浏览正常页面即可中招。
- **场景：** 论坛发帖、评论区、用户个人资料页。

### 3. DOM 型 XSS (DOM-based XSS)
- **原理：** 漏洞存在于**客户端的 JavaScript 代码**中，而不是服务端的响应中。客户端脚本从攻击者可控的 DOM 源（如 `window.location.hash`, `document.referrer`）读取数据，并将其传递给不安全的执行槽（Sink，如 `innerHTML`, `eval()`，`document.write()`）。
- **特点：** 整个攻击过程可能根本不涉及服务器（载荷在 URL 的 `#` 后面，不会发送给服务器）。

## 防护方法

防御 XSS 的核心在于**输出编码**和**安全的内容安全策略**。

### 1. 上下文感知的[[输出编码与转义|输出编码 ]](Context-Aware Output Encoding)
在将不可信数据插入 HTML 文档之前，必须对其进行严格的编码/转义。不同的插入位置（上下文）需要不同的编码规则：
- **HTML 正文：** 转义 `<` `>` `&` `"` `'` 等字符（HTML Entity 编码）。
- **HTML 属性：** 除了字母和数字，其他字符都应转义。
- **JavaScript 上下文：** 插入到 `<script>` 标签内的数据必须进行 Unicode 转义（如 `\u0027`）。
- **CSS 和 URL 上下文：** 同样需要专门的转义规则。

*现代前端框架（如 React, Vue, Angular）在默认情况下会对插入 HTML 的变量进行自动编码，从而大幅减少了 XSS 漏洞。*

### 2. 内容安全策略 (Content Security Policy, CSP)
CSP 是一种通过 HTTP 响应头传递的安全机制。它允许站点管理员声明浏览器可以加载哪些来源的可执行脚本。
- CSP 可以禁止内联脚本（`<script>...</script>`）的执行。
- CSP 可以限制脚本只能从受信任的域名加载。
- 这是一种强大的纵深防御机制，即使应用存在 XSS 漏洞，CSP 也能阻止恶意脚本的执行或数据的外发。

### 3. 使用 HttpOnly Cookie
将敏感的 Cookie（如 Session ID）标记为 `HttpOnly`。这样，即使发生了 XSS 攻击，JavaScript 也无法通过 `document.cookie` 读取到这些 Cookie，从而防止会话劫持。
