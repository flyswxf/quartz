## 什么是注入攻击？

注入漏洞是指应用程序将不可信的数据作为命令或查询的一部分发送给解释器，导致解释器执行了非预期的指令或访问了未经授权的数据。

注入的核心问题在于**代码与数据没有分离**。当数据被错误地当作代码解析时，漏洞就产生了。

## 2. 操作系统命令注入 (OS Command Injection)

当应用程序在调用系统命令（如 `system()`, `exec()`, `Runtime.getRuntime().exec()`）时，直接使用了未经处理的用户输入。

### 漏洞示例
假设一个网站提供 ping 功能：
```bash
ping -c 4 $user_input
```
如果用户输入 `127.0.0.1; cat /etc/passwd`，实际执行的命令变为：
```bash
ping -c 4 127.0.0.1; cat /etc/passwd
```
攻击者成功执行了任意系统命令。

### 防护方法
- **避免调用系统命令：** 尽可能使用编程语言自带的 API 或库来实现所需功能。
- **参数分离：** 如果必须调用外部命令，不要使用通过 Shell 解释的函数（如 `system`）。使用可以将命令和参数作为独立数组传递的 API（如 Python 的 `subprocess.run(["ping", "-c", "4", user_input])`），这样输入就不会被 Shell 解析为多个命令。

## 3. 其他注入类型

- **LDAP 注入：** 针对轻量级目录访问协议查询的注入。
- **XPath/XML 注入：** 针对 XML 文档查询的注入。
- **NoSQL 注入：** 针对 MongoDB 等非关系型数据库的查询注入（例如通过传递 JSON 对象改变查询逻辑）。

## 通用防御原则

防御所有类型注入攻击的根本原则是：**保持控制平面（代码/命令）和数据平面（用户输入）的严格隔离。** 永远不要让数据去影响指令的语法结构。
