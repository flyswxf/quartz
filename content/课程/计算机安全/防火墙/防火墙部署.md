# 防火墙部署 (Firewall Basing)

> [!info] 定义
> 防火墙可以部署在多种平台上：独立运行通用操作系统（如 UNIX/Linux）的主机、预配置的安全设备、路由器/交换机中的软件模块、服务器、虚拟化环境中的虚拟防火墙，以及个人计算机上的软件防火墙。不同的部署方式适用于不同的安全需求和网络规模。

---

## 堡垒主机 (Bastion Host)

> [!info] 定义
> 由防火墙管理员指定的、作为网络安全体系中**关键强点**的系统。通常作为[[应用代理防火墙|应用层网关]]、[[电路级代理防火墙|电路级网关]]或 IPSec 等服务的运行平台，是外部攻击者最可能直接接触的主机。

### 共同特征

> [!abstract] 堡垒主机的九项设计原则

1. **强化操作系统** — 硬件平台运行安全版本的操作系统，构成加固系统（Hardened System）
2. **最小化安装** — 仅安装网络管理员认为必要的服务，如 DNS、FTP、HTTP、SMTP 的代理应用
3. **增强认证** — 用户访问代理服务前可能需要额外的认证步骤；每个代理服务可能要求独立的认证
4. **有限命令集** — 每个代理仅配置为支持标准应用命令集的一个子集
5. **限定访问目标** — 每个代理仅允许访问受保护网络上的特定主机系统
6. **详细审计日志** — 每个代理记录所有流量、每个连接及其持续时间，审计日志是发现和终止入侵攻击的关键工具
7. **小型专用软件** — 每个代理模块是专为网络安全设计的极小软件包。典型 UNIX 邮件应用可能包含超过 $20\,000$ 行代码，而一个邮件代理可能不足 $1\,000$ 行
8. **相互独立** — 各代理之间彼此独立，任一代理出现故障或被发现漏洞时，可单独卸载而不影响其他代理；新服务需求也可随时安装对应代理
9. **只读可执行文件** — 代理通常只在启动时读取配置文件，之后不再访问磁盘。因此文件系统中包含可执行代码的部分可设为只读，使攻击者难以在堡垒主机上安装木马、嗅探器等恶意文件

> [!tip] 以非特权用户运行
> 每个代理以非特权用户身份运行在堡垒主机上的专用安全目录中，进一步限制潜在损害范围。

> [!example] 举例
> 一家企业将一台运行加固 Linux 的服务器部署为 DMZ 区域的堡垒主机，上面仅运行 HTTP 代理和 SMTP 代理。外部用户只能通过 HTTP 代理访问内部 Web 应用，邮件通过 SMTP 代理中转。即使攻击者利用 HTTP 代理的某个漏洞获得访问权，由于代理以非特权用户运行且可执行文件只读，也难以进一步渗透。

## 主机防火墙 (Host-Based Firewall)

> [!info] 定义
> 用于保护**单台主机**的软件模块，通常内置于操作系统中或作为附加软件包提供。与独立防火墙类似，主机防火墙也对数据包进行过滤和流量控制，常部署在服务器上。

### 优势

> [!example] 主机防火墙的三大优势

1. **定制化过滤规则** — 过滤规则可根据主机环境量身定制。不同应用的服务器可实施不同的企业安全策略过滤器
2. **与拓扑无关的保护** — 防护独立于网络拓扑结构，内部攻击和外部攻击都必须经过主机防火墙
3. **纵深防御** — 与独立防火墙配合使用时提供额外的保护层。新型服务器可直接添加到网络中并自带防火墙，无需修改网络防火墙配置

> [!example] 举例
> 一台数据库服务器除了经过企业边界防火墙外，自身也运行主机防火墙，仅允许来自特定应用服务器的 $3306$ 端口（MySQL）连接，拒绝所有其他入站流量。即使攻击者突破了边界防火墙，也无法直接连接数据库。

## 网络设备防火墙 (Network Device Firewall)

> [!info] 定义
> 路由器和交换机等网络设备中内置的防火墙功能，尤其是**包过滤**和**状态检测**能力，用于监控和过滤经过设备的数据包流。通常与堡垒主机和主机防火墙配合使用，提供额外的保护层。

> [!tip] 典型用途
> - 路由器上配置 ACL（访问控制列表）实现基本的包过滤
> - 三层交换机上启用状态检测功能
> - 作为内部网络各网段之间的微分段（Micro-segmentation）手段

---

## 虚拟防火墙 (Virtual Firewall)

> [!info] 定义
> 在虚拟化环境中，服务器、交换机、路由器和防火墙堡垒主机等可以采用**虚拟版本**，共享同一物理硬件。防火墙功能也可由管理虚拟机的 **Hypervisor（虚拟机监视器）** 提供。

> [!note] 虚拟防火墙的特点
> - 虚拟机之间的流量可在 Hypervisor 层面进行过滤，无需经过物理网络设备
> - 支持细粒度的虚拟网络隔离
> - 与软件定义网络（SDN）结合，实现灵活的安全策略

> [!example] 举例
> 在 VMware ESXi 环境中，每台虚拟机可以配备虚拟防火墙规则，即使两台虚拟机位于同一物理服务器的同一虚拟交换机上，它们之间的通信也受虚拟防火墙的检查和控制。

## 个人防火墙 (Personal Firewall)

> [!info] 定义
> 控制个人计算机或工作站与 Internet/企业网络之间流量的防火墙。既可用于家庭环境，也可用于企业内网。通常以**软件模块**形式存在于个人计算机中；在家庭环境中，也可内置于连接所有家庭计算机的路由器中。

> [!note] 与服务器防火墙的区别
> 个人防火墙通常比服务器级防火墙或独立防火墙**简单得多**，核心目标只有两个：
> 1. **拒绝未授权的远程访问** — 阻止外部对本机的主动连接
> 2. **监控出站活动** — 检测并阻断蠕虫和其他恶意软件的外联行为

### 常见实现

| 操作系统        | 防火墙实现                        |
| --------------- | --------------------------------- |
| **Linux**       | netfilter 包（iptables/nftables） |
| **BSD / macOS** | pf 包（Packet Filter）            |
| **Windows**     | Windows Firewall                  |

> [!tip] 配置方式
> 这些防火墙可通过**命令行**或 **GUI 界面**进行配置。

### 默认行为

> [!warning] 默认策略
> 启用个人防火墙后：
> - **入站连接** — 通常**全部拒绝**，除非用户明确允许
> - **出站连接** — 通常**全部允许**

### 高级功能

> [!abstract] 增强保护的可配置功能

- **隐身模式 (Stealth Mode)** — 丢弃未经请求的通信数据包，使系统在 Internet 上"隐身"，让攻击者看起来该系统**不存在**
- **UDP 过滤** — 阻断所有 UDP 数据包，将网络流量限制为仅允许 TCP 数据包通过已开放端口
- **日志记录** — 记录所有防火墙活动，用于检查异常和未授权的网络行为
- **应用级控制** — 允许用户指定**仅选定的应用程序**，或由有效证书颁发机构签名的应用程序，才能提供来自网络的服务访问

### 与 [[#主机防火墙|主机防火墙]] 的对比

| 对比维度     | 个人防火墙       | 主机防火墙      |
| -------- | ----------- | ---------- |
| **部署对象** | 个人 PC / 工作站 | 服务器 / 关键主机 |
| **复杂度**  | 低           | 高          |
| **配置粒度** | 简单（应用级/端口级） | 复杂（定制化规则集） |
| **用户**   | 个人用户        | 网络管理员      |
| **典型功能** | 拒绝入站、监控出站   | 深度包过滤、状态检测 |
| **策略来源** | 用户自行配置      | 企业安全策略     |

## 五种部署方式对比

| 部署方式                      | 部署位置            | 保护范围     | 典型功能        | 适用场景      |
| ------------------------- | --------------- | -------- | ----------- | --------- |
| **[[#堡垒主机\|堡垒主机]]**       | 网络边界/DMZ        | 所有经过的流量  | 应用层代理、电路级代理 | 企业边界、DMZ  |
| **[[#主机防火墙\|主机防火墙]]**     | 单台主机            | 该主机的流量   | 包过滤、状态检测    | 服务器、工作站   |
| **[[#网络设备防火墙\|网络设备防火墙]]** | 路由器/交换机         | 经过该设备的流量 | 包过滤、状态检测    | 网络骨干、网段隔离 |
| **[[#虚拟防火墙\|虚拟防火墙]]**     | Hypervisor/虚拟网络 | 虚拟机间流量   | 虚拟网络过滤、微分段  | 虚拟化/云计算环境 |
| **[[#个人防火墙\|个人防火墙]]**     | 个人 PC / 工作站     | 该主机的流量   | 拒绝入站、监控出站   | 个人用户、家庭网络 |

> [!tip] 纵深防御
> 实际部署中，通常将多种防火墙**组合使用**：网络设备防火墙提供第一层包过滤，堡垒主机执行应用层深度检查，主机防火墙保护关键服务器，虚拟防火墙隔离虚拟化环境中的流量，共同构成纵深防御体系。
