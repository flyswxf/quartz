### 经典 ping 洪泛攻击
这是最基础的 DoS 攻击，也是后续所有攻击变种的基础

- **攻击原理**：利用 ICMP 协议的 ping 功能（正常用于网络连通性测试），攻击者通过高带宽机器，向低带宽目标持续发送海量 ping 请求，直接占满目标的互联网接入链路带宽，让合法流量无法通过，最终实现服务不可用。
- **两个致命缺陷**：
    1. **溯源风险**：数据包使用攻击机真实源 IP，目标可直接从包头获取攻击源地址，轻松完成溯源、封禁；
    2. **反噬自身**：目标会对每个 ping 请求回复响应包，这些流量会全部涌向攻击机，占用攻击机的带宽和性能，不仅削弱攻击效果，还会让攻击行为极易被检测。

### 源地址伪造（Source Address Spoofing）
发送数据包时伪造源 IP，使目标难以基于源地址进行封禁/溯源。

**相较于[[拒绝服务攻击#经典 ping 洪泛攻击|经典 ping 泛洪攻击]]**: 
  - 增加追踪难度。
  - 目标的响应包不会再回到攻击机，而是被分散到互联网的伪造地址处，攻击机不会被反向流量影响，攻击可以无限制持续。更关键的是：如果伪造的地址对应真实主机，这些主机若返回错误数据包，进一步加剧目标的流量拥塞，变相放大了攻击效果。

### SYN 伪造（SYN Spoofing）

#### 背景
在[[TCP 三次握手]]中, 服务端收到 SYN 后会为连接分配一定状态（半连接），等待对方 ACK

#### 核心逻辑如下：
1. **构造恶意流量**：攻击者生成大量 SYN 数据包，每个包的源 IP 都是随机伪造的、无响应的地址，目的 IP 为目标服务器。
2. **生成半开连接，占用系统资源**：服务器收到每一个 SYN 包，都会在 TCP 连接表中创建条目，进入 SYN_RCVD 半开状态，同时向伪造的源 IP 回复 SYN-ACK 包。
3. **无响应导致条目长期占用**：由于源 IP 是伪造的，要么无对应主机，要么主机不会回复 ACK/RST，服务器收不到第三次握手的 ACK，会持续重传 SYN-ACK，在超时前，这条半开连接会一直占用连接表资源。
4. **连接表被占满，拒绝合法连接**：攻击者持续发送伪造 SYN 包，快速填满容量有限的 TCP 连接表。一旦表被占满，服务器无法再处理新的 SYN 请求，包括合法用户的正常连接，最终实现拒绝服务。
5. **攻击持续化**：即使部分条目超时释放，攻击者也会持续发送新的伪造 SYN 包，让连接表始终处于满负载状态，使服务器长期无法响应合法请求。

| 对比维度    | SYN 欺骗攻击                                          | SYN 洪泛攻击                               |
| ------- | ------------------------------------------------- | -------------------------------------- |
| 核心攻击目标  | 系统资源（TCP 连接表、操作系统网络处理代码）                          | 网络带宽（服务器接入链路的容量）                       |
| 攻击核心逻辑  | 用伪造源 IP 的 SYN 包生成大量半开连接，占满 TCP 连接表，让服务器无法处理新的合法连接 | 用海量 SYN 包（源 IP 可真可假）直接打满链路带宽，让合法流量无法传输 |
| 流量规模需求  | 极低，仅需填满容量有限的连接表即可，远达不到链路带宽上限                      | 极高，需要达到链路的最大带宽容量才能实现最佳攻击效果             |
| 攻击利用的缺陷 | TCP 三次握手的状态管理机制缺陷                                 | 网络链路的带宽上限物理限制                          |

## 洪泛攻击（Flooding Attacks）
用海量恶意数据包挤占链路全部带宽，导致路径上的路由器出现拥塞并随机丢包，合法用户的请求几乎无法到达服务器，最终实现服务不可用

| 攻击类型     | 核心利用协议               | 攻击优势                                                                                                                                                                          |
| ------------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ICMP 洪泛    | ICMP（互联网控制消息协议） | 使用防火墙放行的关键ICMP包: ICMP 目标不可达、超时数据包. 由于这类数据包可以包含所谓 “触发报错的错误数据包” 的部分内容，因此可以被构造得相对较大，进一步提升其淹没链路的攻击效果。 |
| UDP 洪泛     | UDP（用户数据报协议）      | 无连接、无需握手，攻击者可无限制发送海量数据包，攻击效率极高；无需等待响应，入向带宽占满即攻击成功                                                                                |
| TCP SYN 洪泛 | TCP（传输控制协议）        | 利用业务必须放行的 TCP 连接请求包，难以被基础防火墙拦截                                                                                                                           |

## 反射攻击（Reflection Attacks）
- **核心逻辑**：攻击者伪造源 IP 为目标服务器的 IP，向互联网上的大量合法服务器（反射器）发送请求。这些服务器收到请求后，会将响应数据包发送给被伪造的源 IP（即目标服务器）。
- **攻击优势**：
    1. **隐蔽性极高**：目标服务器收到的攻击流量全部来自合法的第三方服务器，很难追溯到真实的攻击者。
    2. **绕过封禁**：由于反射器往往是正常的公网服务（如 DNS、NTP 服务器），目标如果直接封禁这些 IP，可能会影响正常业务。

## 放大攻击（Amplification Attacks）
- **核心逻辑**：放大攻击通常建立在反射攻击的基础上（即**反射放大攻击**）。攻击者利用某些 UDP 协议的无连接特性，发送一个很小的请求包，触发服务器返回一个体积巨大（成百上千倍）的响应包给目标。
- **常见放大方式**：
	- **广播放大**: 将原始请求发送到某个网络的广播地址。这样一来，该网络中的所有主机都可能对该请求做出响应，最终生成海量的响应流量. 如[[拒绝服务攻击#Smurf 攻击（ICMP 广播放大攻击）]]
		- **限制**
			- 只能使用无连接的协议(如 UDP )
			- TCP 是面向连接的，无法向广播地址发送请求，因此不能被用于这类攻击。
    - **DNS 放大**：利用 DNS 的 ANY 请求，小请求包（几十字节）可换来大响应包（几千字节），放大倍数可达 50 倍以上。


### 案例
##### Smurf 攻击（ICMP 广播放大攻击）
1. 攻击者发送伪造了目标 IP 源地址的 ICMP Echo Request（ping 请求）包，目标地址是某个网络的广播地址；
2. 广播地址的特性是：网络内的所有主机都会收到这个 ping 请求；
3. 网络内的所有主机会向伪造的源地址（攻击目标）回复 ICMP Echo Response 包；
4. 最终效果：攻击者发送 1 个请求包，触发数十、数百个响应包涌向目标，实现流量的批量放大。
