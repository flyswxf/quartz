### rewrite (缩写 rew)
>从初始项开始，按照重写规则一步步执行，直到不能再重写为止

*   **行为特点**：
    *   **单路径（Single Path）**：它只展示系统演化的**一种**可能性。如果有多个规则同时适用，`rewrite` 只会“贪婪”地选择其中一条路径走下去。
    *   **自顶向下（Top-down）**：倾向于先匹配最外层的结构。
    *   **规则公平（Rule-fair）**：尝试给每个适用的规则执行机会，但在特定情况下（如顶层无限循环）可能会忽略内部子项。
*   **适用场景**：快速查看系统能否跑通，或者用于确定性的系统。

### frewrite (缩写 frew)
>专门为了解决并发对象系统中的“饥饿”问题。
*   **行为特点**：
    *   **位置公平（Position-fair）**：这是核心。在并发系统中，`frewrite` 会轮询项中的不同位置，确保每个部分（子项）都有机会向前演化，防止某一部分霸占执行权。
    *   **自底向上（Bottom-up）**：通常先处理子项。
*   **适用场景**：面向对象系统（Object-Oriented Modules），或者当 `rewrite` 陷入局部无限循环时。

### search
>探索完整的可达状态空间

*   **行为特点**：
    *   **全路径探索**：使用**广度优先搜索**遍历所有可能的状态分支。
    *   **逻辑查询**：可以查找是否存在某种路径到达特定状态。
*   **适用场景**：验证系统的安全性（Safety properties）、查找死锁、证明某些状态不可达。

## 语法速查表

### rewrite & frewrite

```maude
rew  [<步数>] <初始项> .
frew [<步数>] <初始项> .
```

*   **示例**：
    *   `rew initialTerm .` (无限重写，直到停止)
    *   `rew [10] initialTerm .` (最多执行10步)

### search

```maude
search [<解的上限>, <深度上限>] <初始项> <箭头> <目标模式> [such that <条件>] .
```

*   **参数说明**：
    *   `[<解>, <深度>]`: 
        *   `[1]` : 只找第 1 个解。
        *   `[1, 10]` : 只找第 1 个解，且搜索深度不超过 10 层。
    *   **箭头类型**:
        *   `=>*` : **0步或多步** (搜所有可达状态)。
        *   `=>!` : **最终状态** (进得去出不来的状态)。
        *   `=>+` : **1步或多步**。
        *   `=>1` : **仅1步**。
*   **常用套路**：
    *   **找结果/死锁**：`search initialTerm =>! X:State .`
    *   **找特定状态**：`search initialTerm =>* X:State such that P(X:State) .`

## 示例：读写者系统 (Readers-Writers)

这是一个经典的并发系统，用于演示 `search` 如何验证系统的不变量（Invariants）。

### 1. 系统定义
```maude
mod READERS-WRITERS is
  sort Nat .
  op 0 : -> Nat [ctor] .
  op s : Nat -> Nat [ctor] .
  
  sort Config .
  op <_,_> : Nat Nat -> Config [ctor] . --- <readers, writers>
  
  vars R W : Nat .
  
  rl < 0, 0 >    => < 0, s(0) > .   --- writer starts (只有没人读写时才能进)
  rl < R, s(W) > => < R, W > .      --- writer ends
  rl < R, 0 >    => < s(R), 0 > .   --- reader starts (只要没人写就能进)
  rl < s(R), W > => < R, W > .      --- reader ends
endm
```
初始状态：`< 0, 0 >` (0个读者，0个写者)。

### 2. 使用 `search` 验证不变量

我们希望验证两个属性：
1.  **互斥 (Mutual Exclusion)**：不能同时有人读和有人写。
    *   **反例模式**：`< s(N), s(M) >` (读者 > 0 且 写者 > 0)。
2.  **单写者 (One Writer)**：同一时间最多一个人写。
    *   **反例模式**：`< N, s(s(M)) >` (写者 > 1)。

#### 无界搜索 (Unbounded Search) - **慎用！**
```maude
search < 0, 0 > =>* < s(N:Nat), s(M:Nat) > .
```
*   **问题**：由于 Reader 可以无限增加 (`< R, 0 > => < s(R), 0 >`)，状态空间是无限的。
*   如果系统是安全的（找不到反例），这个命令**永远不会停止**。

#### 有界搜索 (Bounded Search) - **推荐**
为了在有限时间内得到结果，我们可以限制搜索深度（例如 100,000 步）：

```maude
search [1, 100000] < 0, 0 > =>* < s(N:Nat), s(M:Nat) > .
```
*   **含义**：在 1 到 100,000 步的范围内，搜索是否存在违反互斥的状态。
*   **结果**：`No solution`。
*   **结论**：在深度 100,000 以内，系统满足互斥性。虽然不是绝对证明，但在工程上提供了很高的置信度。
