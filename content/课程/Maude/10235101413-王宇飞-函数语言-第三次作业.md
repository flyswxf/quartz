# Question 1: Clock

系统规则修改为：
`rl clock(T) => clock((T + 3) rem 24) .`

## 1. What is the reachable set of values of T from clock(0)? 
`{0, 3, 6, 9, 12, 15, 18, 21}`

## 2. Is 0 <= T < 24 still an invariant? 
是

可达状态集是 `{0, 3, 6, ..., 21}`。集合中的每一个数都满足 `0 <= T` 且 `T < 24`。

## 3. Write the search command to try to falsify it. 

```maude
search clock(0) =>* clock(T) such that T < 0 or T >= 24 .
```


# Question 2: Deadlock Freedom

## 1. Does rule \[dupl] help or hurt deadlock freedom?
Hurt
\[dupl] 虽然增加了资源，但没有改变资源短”的本质结构。它只是把死锁的规模扩大了，增加了系统进入死锁状态的可能性和路径，所以它对死锁自由是有害的。

## 2. Modify the module to require three resources per process.

完整的 Maude 代码如下：

```maude
mod PROCS-RESOURCES-3 is
  sorts State Resources Process .
  subsorts Process Resources < State .
  ops res null : -> Resources [ctor] .
  op p : Resources -> Process [ctor] .
  op __ : Resources Resources -> Resources [ctor assoc comm id: null] .
  op __ : State State -> State [ctor ditto] .

  rl [acq1] : p(null) res => p(res) .
  rl [acq2] : p(res) res => p(res res) .
  --- 获取第3个资源
  rl [acq3] : p(res res) res => p(res res res) .
  --- 集齐3个才释放
  rl [rel] : p(res res res) => p(null) res res res .
  rl [dupl] : p(null) res => p(null) res p(null) res .
endm
```

# Question 3: Readers-Writers

## 1. Is "every writer eventually enters the critical section" an invariant or a liveness property?

Liveness Property 
这句话里有 "eventually"这个词，这是典型的 Liveness 标志。它不是在说当前状态是不是绝对的，而是在说未来的某个时刻能不能达成目标。

## 2. Could you still use search directly to falsify it?

No
search 命令只能搜索可达状态，也就是它只能用来验证 Invariants。
要证伪 Liveness需要寻找一个无限的循环，在这个循环里 Writer 一直在等，永远没机会进。
